# 合并静态Demo到交付中心

## 输入与现有结构

- 定位实际项目根目录，阅读 `portal/交付门户说明.md`、`requirements.js` 和相关渲染代码，检查目标需求的文档与独立HTML。
- 根目录 `index.html` 为交付中心快捷入口；`portal/` 为共用界面；`01-需求档案/` 保存各需求阶段产物。
- 用户要求合并即执行本地接入，不重复询问是否开始。编号沿用目标需求；无编号先询问用户。
- 未完成关键Demo或输入缺失时指出缺项，不用占位页面冒充已交付需求。

## 交付中心信息架构

1. 左侧「概览」展示全部真实需求列表；Demo导航按状态分组。沿用门户现有状态枚举，无明确进度时可标记待评审并说明它是交付阶段，不能自行宣称已上线。
2. 点击需求后右侧呈现该需求内容。顶部仅显示实际涉及的客户端，并固定保留「业务流程」。在线客服端口可为移动端H5、管理后台等，无涉及端不展示。
3. 选中客户端后，下方左侧按任务列主要场景，可另列状态与异常；右侧展示选定场景的可交互HTML。
4. 业务流程展示本次需求自己的流程，包含必要角色、决策、异常与恢复分支，并与场景导航对应。
5. Demo右上角提供「需求规则」按钮，点击打开右侧抽屉，不再提供原「需求文档」下载操作。抽屉标明当前需求，并只展示本需求实际涉及的客户端；单端展示该端，多端通过Tab查看各端规则。

## 接入步骤

- 在 `requirements.js` 的实际数据结构中新增或更新目标项，保留其他需求和稳定编号；同一需求不重复创建条目。
- 填写编号、名称、摘要、状态、更新时间、版本、业务、范围、文档、客户端、各端需求规则、场景及流程内容。字段沿用现有代码，必要扩展再同步渲染逻辑。
- 文档路径指向真实需求单、PRD与UX设计需求表；场景URL指向独立HTML。路径相对于 `portal`，正确处理中文、空格、查询参数和hash。
- 客户端沿用现有约定：管理后台可用 `id: admin, viewport: desktop`，移动H5可用 `id: h5, viewport: mobile`；只配置涉及端。
- 每个场景包含稳定id、名称、描述、分类与可直接打开的URL，例如 `...?scene={场景id}`。嵌入时通过已有机制附加 `embed=1`，避免重复问号或覆盖原有参数。
- 当前门户最初仅服务 FR-wenkf-001，流程图可能存在写死节点。新增不同需求时检查流程渲染是否按需求切换；按需改为需求配置驱动，不能仅替换标题后继续展示旧客服统计流程。
- 修改根入口或README时保留相对路径和hash跳转。独立打开、重置和放大演示沿用已有能力；保留需求文档源文件及配置中的文档路径，但不恢复Demo右上角的文档下载按钮或弹窗。

## 整理各端需求规则

- 读取本需求的已确认需求单、PRD、UX设计需求表及最新修订，按客户端提炼规则；遇到业务冲突先澄清，不让规则摘要改变原需求含义。
- 在每个实际涉及的 `clients` 项内配置 `rules: [{title, items: [规则文字]}]`，由抽屉按端渲染。每组用短标题，每条用简短、易懂的完整句子，不照搬整份PRD。
- 根据需求选取入口与使用范围、权限、主要操作、关键业务口径、日期或状态限制、异常恢复及明确排除项。保留会影响理解的条件，例如计数对象、归属、去重和范围；省去开发细节、内部功能编号和无关背景。
- 共用规则可在各适用端分别列出，但不能将管理后台专属规则放入H5，或用旧需求规则充当新需求规则。分组数量随内容确定，不固定复制FR-wenkf-001的五组主题。
- 新接入需求的每个涉及端都应有有效规则；缺少关键依据时明确补齐问题，不把「尚未整理」当作已完成交付。
- 打开抽屉默认选中当前正在查看的客户端；从业务流程页打开时默认首个客户端。切换Tab只切换抽屉中的规则，不改变底层Demo场景；切换需求后不可残留旧需求规则。
- 保留右侧抽屉的独立滚动、长内容阅读及窄屏适配；支持关闭按钮、Esc和点击遮罩关闭，支持键盘切换Tab。关闭后能继续查看原Demo。

## 状态和发布边界

- 门户当前状态仅保存在当前浏览器，不代表真实研发进度，也不表示多用户同步；新增需求不能覆盖旧需求的本地状态。
- 参考截图中的其他需求不是真实需求，不录入假记录补齐列表。
- 本地接入不自动包含上传、部署、改仓库可见性或启用Pages。仅在用户明确要求外部同步时按其授权执行。
- 本项目GitHub仓库为私有，用户已选择保持私有；仓库HTML链接是源码入口。没有完成可验证的页面部署前，不宣称可通过GitHub链接在线运行Demo，不把仓库自动改为公开。

## 完成检查

- 在浏览器检查概览与状态分组，新需求可进入、旧需求仍可访问，切换需求和客户端不会串场景。
- 校验所有文档/HTML路径、每个场景深链接及刷新后的路由；独立模式与嵌入模式都能运行。
- 核对所有涉及端和主要场景，确认未涉及端不显示；流程图确实属于所选需求。
- 验证流程节点跳转（如有）、返回概览、重置、独立打开及本地状态行为；检查移动框或桌面画布适配。
- 检查右上角仅保留「需求规则」入口，抽屉中的需求身份、实际涉及端与规则正确；验证默认端、Tab内容隔离、键盘切换、关闭、重新打开及切换需求后的内容。多端可用临时验证页面检查，但不得向正式需求添加虚构客户端。
- 核对规则摘要与已确认文档一致，简短但不遗漏关键条件；没有跨端串规则、恢复旧文档下载弹窗或复制旧需求口径。
- 保存概览、主要场景、业务流程和需求规则抽屉预览到根目录 `02-交付预览/`；明确未验证项，不把源文件路径当作线上预览地址。
- 交付总览入口和更新说明，列出接入需求编号、涉及端、主要场景及本次验证结果。
