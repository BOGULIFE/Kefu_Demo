# 需求单：工单模板用户工单导出

## 1. 基本信息

| 项目 | 内容 |
| --- | --- |
| 需求编号 | FR-wenkf-004 |
| 需求名称 | 工单模板用户工单导出 |
| 产品 | 右豹在线客服 |
| 日期 | 2026-11-26 |
| 当前阶段 | 需求单V1.1，已补充Excel列顺序、历史字段和导出数量上限 |
| 涉及端口 | 客服管理后台；H5用户端无新增功能 |

## 2. 需求背景

已有用户工单需求支持管理员配置工单类型（表单模板），用户按模板提交信息，后台处理用户工单。FR-wenkf-002原范围未包含工单导出，本需求以独立编号补充该能力，不将旧需求的排除项解释为永久禁止导出。

本次需要在工单类型配置模块中，为每个模板增加“导出”操作，让管理员按用户工单状态及提交日期提取该模板收集的信息，形成Excel文件，便于后续整理与业务处理。图片、视频通过链接保留在Excel内，用户可通过链接访问对应附件。

现状依据为项目已有档案及用户描述，尚未对现网页面逐项核实；不据此推断现网已有其他导出入口或完整导出能力。

## 3. 使用用户与权限范围

| 端口 | 身份 | 本次能力及范围 |
| --- | --- | --- |
| 前端／H5用户端 | 提交工单的用户 | 无新增操作；其通过模板提交的信息可被有权限的管理员导出 |
| 管理后台 | 管理员 | 在工单类型配置中导出当前模板、当前组织范围内的用户提交工单 |
| 管理后台 | 普通客服／模板处理人 | 不因担任处理人获得模板导出权限；无新增导出能力 |
| 其他端 | 无新增身份 | 无新增页面或操作 |

后台导出权限与附件链接访问规则分别约束：只有管理员可发起导出；导出的图片、视频链接不设访问权限，持有链接即可访问，无需登录或工单归属校验。这一链接规则为用户明确要求，不将其扩大解释为Excel文件、工单详情或其他后台页面公开访问。

## 4. 关联页面与入口

- 入口：客服后台 → 工单处理 → 工单类型配置。
- 在每个工单模板的操作区域新增“导出”，操作对象明确为该模板。
- 点击后进入导出条件选择界面，提供工单状态多选、工单提交日期选择及确认导出操作。
- 保留现有模板配置、用户提交及工单处理流程；本次不增加独立工单处理菜单。
- 方案设计：导出条件使用弹窗承载，展示目标模板名称，提供取消操作；取消后返回模板列表，不生成文件。

## 5. 需求内容与业务口径

### 5.1 导出对象及范围

- 每次针对一个模板，按模板关联关系识别工单，不仅按模板名称匹配。
- 仅导出当前模板收集的用户提交来源工单，不混入客服创建来源或其他模板的工单。
- 数据范围为管理员当前组织内有权访问的记录，不提供跨组织导出。
- 在单次导出数量上限内，导出全部符合条件的工单，不受模板列表或工单列表当前分页限制；数量上限见5.7。
- 工单模板、组织权限、勾选状态及提交日期条件同时生效；任一条件不满足均不纳入。

### 5.2 工单状态多选

- 点击导出后支持勾选多个用户工单状态，导出任一所选状态的工单。
- 状态为“处理中”“已完结”，沿用FR-wenkf-002的用户提交工单定义；不增加待接收状态，不改变状态流转。
- 仅勾选处理中时，只导出处理中工单；仅勾选已完结时，只导出已完结工单；两项均勾选时，导出两类工单。
- 按导出时工单的当前状态判断，不按提交时或所选日期当日的历史状态判断。
- 方案设计：打开时默认勾选全部状态；至少勾选一项才可确认导出，清空勾选不解释为全部状态。

### 5.3 工单提交日期

- 提供“全部”“自定义区间”选项，默认选择“全部”。
- “全部”不施加提交日期限制，导出系统实际保留且符合其他条件的记录，不虚构历史起点。
- “自定义区间”按北京时间选择开始日期和结束日期，包含起止两天；例如11月1日至3日，包含1日零点起至3日全天的提交记录。
- 筛选依据是工单提交时间，不是处理、移交或完结时间。
- 同一天可以作为开始和结束日期，表示导出该日全天提交的工单。
- 方案设计：自定义时起止日期均必填，开始日期不得晚于结束日期；切回“全部”后不应用先前填写的日期，不自行增加最大区间限制。

### 5.4 Excel内容

已确认：导出格式为Excel，包含符合条件的用户工单信息；模板中的图片、视频类型字段以附件链接呈现，不将媒体内容嵌入单元格。

已确认的列结构及内容规则：

| 列位置 | 列内容与顺序 |
| --- | --- |
| 第一列 | 提交用户ID |
| 第二列 | 工单状态 |
| 第三列 | 当前负责人 |
| 第四列 | 提交日期 |
| 第五列起 | 按当前表单配置的填写标题及其顺序依次排列 |
| 当前表单字段之后 | 接续排列历史字段变更中已被删除的字段，保留历史填写内容 |

- 表单字段有内容时显示实际内容，无内容时单元格为空；历史工单未填写的当前字段、后续工单不存在的历史已删除字段均留空。
- 历史已删除字段不能因当前表单不再配置而丢失；保持字段与答案正确对应，不将旧答案误标到其他字段下。
- 本次固定基础列为上述四列，不额外增加工单编号或独立处理结果列。若处理结果本身属于表单配置字段，则按该表单字段规则导出。

其余呈现方式为方案设计：

| 内容 | 导出方式 |
| --- | --- |
| 行粒度 | 一条工单一行，同一工单不因多选状态或存在多个附件而重复生成工单行 |
| 文本、长文本 | 保留实际填写内容 |
| 单选、多选 | 展示所选选项的可读文本，多选值在同一单元格内分隔 |
| 图片、视频 | 对应字段单元格展示完整附件URL；同字段有多个附件时逐项换行列出，保留全部链接 |
| 提交日期格式 | 展示北京时间的工单提交日期，具体格式在PRD阶段细化 |

历史已删除字段之间的排列顺序、字段重名或删除后重建的识别方式在PRD阶段细化；不能仅按标题相同就将不同字段的答案错误合并。本次处理历史字段导出，不以新增模板编辑功能为前提。

### 5.5 图片、视频链接

- 用户明确要求：导出的附件链接不设访问权限，持有链接即可访问，不要求登录后台或拥有对应工单权限。
- 链接必须指向该工单该字段实际提交的附件，不能只输出附件ID、后台详情页地址或需要登录才能访问的地址。
- 同一工单的多个图片、视频附件不得漏导、串到其他字段或其他工单。
- “不设访问权限”描述的是访问鉴权要求，用户未提出永久有效或新增链接有效期配置；不将其等同于附件永久保存承诺。
- 方案设计：本次不新增链接过期时间选择项；正常保留的附件在导出后应可直接访问，不能因复用短时后台登录地址导致文件下载后立即失效。具体链接实现和资源保存期限由后续技术评审明确。

### 5.6 反馈与一致性

以下为方案设计：

- 点击确认导出时确定本次模板、筛选条件及数据截至时点；文件内状态和记录范围使用同一结果口径，避免生成过程中状态变化导致重复或遗漏。
- 生成中展示进度状态并防止重复点击触发相同任务；成功后提供Excel下载结果。
- 没有符合条件的工单时提示“暂无符合条件的工单”，保留筛选条件供修改，不提示虚假的导出成功。
- 失败时明确提示并允许重试，不把失败当作无数据，不下载缺失部分记录却声称完整的文件。
- 执行时校验当前管理员身份、模板及组织范围，不能仅凭页面按钮可见就放行。

### 5.7 导出数量上限及Demo边界

- 已确认：单次导出的工单数据量暂定最大5000条，按工单记录数计算，不含表头行；具体上限由后续研发时开发人员配置。
- 该上限不改变模板、状态、日期及组织权限筛选口径，不等于只导出当前页面记录。
- 超过上限时的处理方式在PRD阶段形成方案，不默认静默截取前5000条并提示完整导出成功。
- 已确认：后续静态Demo无需验证此项数量上限，无需构造5000条数据、进行数量拦截测试或验证研发配置能力；实际系统的数量限制由研发实现并验证。

## 6. 用户使用路径流程

### 路径一：按状态导出全部提交日期

管理员进入“工单处理 → 工单类型配置” → 找到目标模板 → 点击“导出” → 选择一个或多个状态 → 提交日期保持默认“全部” → 确认导出 → 在单次导出上限内获取全部符合条件的工单Excel → 继续停留在模板配置场景。

### 路径二：按状态及自定义日期导出

管理员点击模板“导出” → 勾选状态 → 提交日期选择“自定义区间” → 选择起止日期 → 确认导出 → 获取所选起止日期内提交且当前状态符合勾选项的工单Excel。

例如：某工单11月1日提交、11月5日完结。导出11月1日至3日提交、当前状态为已完结的记录时，应包含该工单；不能按11月5日完结时间将其排除。

### 路径三：查看导出附件

持有Excel的人查看图片／视频字段 → 获取对应附件链接 → 直接打开附件，无需登录或工单权限验证。多附件字段可分别访问每个链接。

### 路径四：取消、空数据及失败

管理员可取消条件选择并返回模板列表；无匹配记录时修改条件后再次导出；导出失败时保留条件并重试，不影响原工单及模板配置。

## 7. 不允许出现的情况

- 导出其他模板、其他组织或客服创建来源的工单。
- 普通客服通过直接调用导出操作获得模板数据，或把附件公开访问规则扩展为后台工单公开。
- 状态多选仅处理其中一项、漏导另一项，或将未勾选的状态纳入。
- 按提交时状态代替导出时当前状态筛选。
- 日期选择“全部”时仍受旧自定义区间限制，或自定义区间漏掉结束日期当天记录。
- 以完结时间、移交时间代替提交时间过滤。
- 只导出当前页、因附件数量拆出重复工单行，或未说明即截断导出记录。
- 图片、视频嵌入Excel替代所要求的链接，多个附件只保留一个，或链接对应错误附件。
- 附件链接要求后台登录、工单归属权限，或只提供无法访问附件的内部标识。
- Excel前四列顺序错误，当前表单字段顺序与配置不一致，或历史已删除字段未接续在当前表单字段后。
- 表头与实际答案错配、空值被伪造为有内容、历史已删除字段的答案丢失，或失败及空数据被提示为完整导出成功。
- 将暂定5000条作为永久不可配置的固定值，或要求静态Demo验证此数量上限。
- 将自行设计的默认状态、多附件排布及反馈交互描述为用户已逐项确认。

## 8. 这次不做的内容

本次限定为单模板用户工单Excel导出。以下未被提出，不默认扩展：

- 多模板合并或批量导出、跨组织导出、客服创建来源工单导出。
- H5新增导出入口、普通客服新增模板导出权限。
- 图片／视频直接嵌入Excel、附件打包下载。
- 模板创建编辑改造、工单状态流转改造、统计报表及旧需求统计口径调整。
- 自选导出列管理、定时导出、邮件发送、独立导出任务管理中心。
- 附件链接权限配置、用户可配置链接有效期或附件永久保存能力。
- 静态Demo中的5000条数量上限验证、大数据量测试及研发配置能力验证；实际系统仍需按配置实现导出上限。

## 9. 不明确／未定的内容

已确认：Excel前四列依次为提交用户ID、工单状态、当前负责人、提交日期；之后按当前表单填写标题顺序排列，再接续历史已删除字段；有内容显示内容，无内容留空。单次导出暂定最大5000条，由研发配置，Demo无需验证此项。

待细化：超过数量上限时的处理方式尚未确定，影响超量场景的操作结果；由产品在PRD阶段形成方案供评审。其余后续细化项如下，多附件排布等方案设计不视为用户逐项确认。

| 项目 | 影响 | 后续确认方／阶段 |
