## 2. 背景、目标与范围

### 2.1 背景与目标

FR-wenkf-002支持管理员配置表单模板、用户提交及后台处理，但原范围不含导出。本需求独立补充模板收集信息的Excel提取能力，便于管理员按状态、提交日期整理业务资料，并通过Excel内的链接查看图片及视频。

既有路径为“客服后台 → 工单处理 → 工单类型配置”。变更后在各模板操作区新增“导出”，在当前配置场景完成条件选择、生成与下载，不新增独立处理菜单。

目标是：导出对象准确、符合条件的记录完整、历史字段答案不丢失且不串列、附件链接可直接访问；失败及超量有明确反馈，不以截断文件冒充完整结果。不新增统计指标或改变工单状态流转。

### 2.2 用户、端与权限

| 角色／端 | 职责与权限 |
| --- | --- |
| 管理员／客服管理后台 | 对当前组织内可访问的单个模板发起导出及下载本次文件，不受“当前负责人是否本人”限制 |
| 普通客服、模板处理人／后台 | 无新增导出权限；被指派处理工单不等于可导出模板 |
| 提交用户／H5 | 无新增页面或操作；沿用既有提交、记录及详情流程 |
| 附件链接持有人 | 可直接访问导出所指向的图片／视频，无需登录或工单归属校验；不因此获得Excel下载或后台访问权限 |
| 其他端 | 不涉及 |

### 2.3 本次范围及排除项

范围：单模板导出入口、状态多选、全部／自定义提交日期、Excel生成下载、当前及历史已删除字段、附件URL、权限及一致性、数量上限和异常恢复。

不包含：多模板合并／批量导出、跨组织导出、客服创建来源导出、H5导出、普通客服导出、媒体嵌入Excel、附件打包、自选列、定时导出、邮件发送、独立任务中心、模板编辑改造、工单流转改造、统计报表、链接权限或有效期配置、附件永久保存承诺。静态Demo不承担5000条数量拦截、大数据量及研发配置能力验证；真实系统仍须实现并验证上限。

## 4. 用户路径与业务流程

1. 管理员进入工单类型配置，定位一个模板，点击该行“导出”。
2. 校验当前身份、组织、模板可访问性，打开P02并展示模板名称。方案设计：状态默认全选“处理中、已完结”，日期默认“全部”。
3. 管理员按需调整状态、选择自定义起止日期；点击确认才提交条件，不在勾选时直接生成文件。
4. 校验条件；服务端接受本次有效操作时确定数据截至时点T0及条件快照，计算符合条件的工单数N，读取本次生效上限L。
5. N=0：显示“暂无符合条件的工单”；N>L：显示超量提示；两者均不生成文件，保留条件供调整。
6. 1≤N≤L：生成完整Excel。生成中锁定本次条件并防重复提交；成功后显示导出条数及下载入口。
7. 管理员下载Excel，查看基础信息、当前表单字段、历史已删除字段及附件链接；完成后可关闭弹窗返回模板列表。
8. 校验失败原位修正；生成失败保留条件供重试；下载失败重试下载同一文件。身份／组织／目标失效时停止操作，清除不可访问的结果并返回可访问页面。

取消仅用于尚未提交的条件选择，不生成文件。生成过程、重新导出及关闭行为按F08执行，不增加后台任务管理页面。

## 5. 功能详细规则

### F01：模板入口与目标校验

- 前置条件：管理员已登录并可进入当前组织的工单类型配置。每个可访问模板操作区提供“导出”，操作始终绑定稳定模板标识，模板重名或改名不改变关联对象。
- 点击后P02只读展示目标模板名称，不能在弹窗内切换模板。不要求存在工单才允许打开；无记录通过F04空数据反馈。
- 模板列表加载、空态、分页、原配置操作沿用已有行为；导出不改变其查询条件、页码或排序。列表无模板时无伪造的可导出对象。
- 打开弹窗及实际执行时均校验管理员资格、组织和模板。普通客服不展示入口，直接请求也拒绝；模板不存在、已不可访问时提示“模板不存在或不可访问，请返回列表刷新”，不复用旧模板数据。
- 取消或关闭未提交的弹窗返回原模板列表，不写入模板或工单。再次从模板行打开按默认条件初始化，不携带其他模板的选择及文件。

### F02：状态多选

- 输入仅包含“处理中”“已完结”，默认均选中。两项之间为“或”，与模板、来源、组织及日期条件为“且”。
- 至少选择一项。全不选时不能确认，显示“请至少选择一个工单状态”；服务端也校验，不将空集合解释成全部。
- 仅选处理中／已完结时，只含对应状态；全选时含两类，不增加待接收或其他客服创建状态。
- 以T0当前状态筛选并输出状态，不以提交时或所选日期当日状态判断。状态发生变化后如需新结果，应重新导出。
- 非法状态值拒绝执行并提示重新选择，不静默映射成合法状态。

### F03：提交日期筛选

- 默认“全部”，不施加提交时间限制，只处理系统实际保留且符合其他条件的记录，无预设历史起点。
- “自定义区间”提供开始、结束两个日历日期，均必填，允许同日；开始不得晚于结束。缺失或不合法时原位提示并保留其他输入，不发起导出。
- 日期按北京时间（Asia/Shanghai，UTC+08:00）解释。开始日00:00:00包含，结束日次日00:00:00不包含，即左闭右开区间；包含结束日全部精度的记录，不仅包含到23:59:59整数秒。
- 筛选依据为工单成功提交时间；移交、处理、完结时间不替代提交时间。
- 切回“全部”立即停止应用已填日期。方案设计：同一次弹窗会话中保留已填日期，切回自定义时可继续修改；全部模式下旧日期即使不合法也不影响确认。
- 不增加最大日期跨度或额外历史限制。方案设计：允许选择未来日期，实际无记录时按空数据处理；不虚构尚未提交记录。
- 输入变动仅修改待提交条件；确认时读取完整组合条件。无结果预览列表，不增加结果分页、搜索或自动查询。

### F04：导出集合、数据截至时点与数量限制

符合条件集合同时满足：当前管理员授权组织范围、目标模板稳定关联、来源为用户提交、T0状态属于勾选集合、提交时间符合日期条件。客服创建工单即使同名或关联同一用户也不纳入。

方案设计：有效确认被服务端接受时取T0；以T0为基准冻结记录集合、状态、当前负责人、提交信息、答案及附件引用、当前模板字段顺序和历史字段清单。T0不是所选日期的结束时间。具体快照／一致性实现由研发选择，不指定数据库结构或接口。

- 只按稳定工单身份去重，一条工单一行；同一用户多次成功提交的不同工单分别保留，多状态及多附件不复制行。
- 不受模板列表、工单列表的当前页或“指派给我”等列表条件影响；只使用本次弹窗明确提交的条件和授权范围。
- T0后新提交、移交、完结或模板变化不混入本次结果。T0后权限变化按第8节处理，不能借快照继续访问已失去权限的数据。
- 数量上限按数据行计数，不含表头。暂定L=5000，由开发人员配置；不是前端不可变常量，也不提供管理员上限设置页。
- 方案设计：N=L允许完整导出；N>L整次拦截，不生成文件、不截断、不自动分批、不增加分页下载。提示“符合条件的工单共N条，超过单次导出上限L条，请缩小提交日期范围或调整状态后重试”。
- N和生成记录使用同一结果集合，不能先按旧数量通过，再以新数据多导或漏导。L在本次执行时读取并固定；后续配置变更作用于新操作，不在同次生成中变动判定。
- 无记录显示“暂无符合条件的工单”，不生成只有表头的文件，不显示导出成功。
- 若无法可靠获取完整集合、历史字段或答案，按生成失败处理，不下载部分结果并声称完整。数据核实不得通过标题匹配猜测补齐。

### F05：Excel内容与文件呈现

已确认的列顺序如下，基础列固定四列，不额外增加工单编号、独立处理结果、完结时间或统计汇总列。

| 位置 | 表头 | 内容与口径 |
| --- | --- | --- |
| 第1列 | 提交用户ID | 工单成功提交时绑定的用户ID，不取表单填写的账号，也不取客服账号 |
| 第2列 | 工单状态 | T0的“处理中”或“已完结” |
| 第3列 | 当前负责人 | T0负责人；移交后为接收人，已完结保留最后负责人，不取完结操作者或模板默认处理人 |
| 第4列 | 提交日期 | 工单成功提交时间，显示为北京时间日期时间 |
| 第5列起 | 当前表单填写标题 | 按T0当前配置的字段顺序逐列输出，包括本批结果均无答案的当前字段 |
| 当前字段之后 | 历史已删除字段标题 | 按F06补列并保留历史答案 |

以下为方案设计：

- 格式为`.xlsx`，一个工作表，名称“用户工单”；第一行为表头、之后一条工单一行，不插入标题行、合计行或独立说明行改变列位置。
- 提交日期格式`YYYY-MM-DD HH:mm:ss`，保留原始时间精度用于筛选与排序，显示精度不反向改变数据边界。工单按提交时间升序排列，同时间使用稳定工单标识排序；标识用于排序但不新增导出列。
- 当前负责人显示姓名；同名时附加可区分的现有客服标识。历史失效账号有姓名则保留可识别名称，无可读名称但有稳定标识则显示该标识，不以模板默认处理人代填。无法确定归属时按数据质量问题处理。
- 用户ID、选项及表单文本以文本值写入，保留前导零和长数字；`0`、`false`等有效值不能当成空值。用户输入以`=`、`+`、`-`或`@`等开头时也按文字保存，不作为Excel公式执行。
- 文本／长文本保留实际内容及换行；单选输出提交时所选可读文本，多选保留全部所选项、按提交时表单选项顺序逐项换行。选项后来重命名或删除不改写历史答案。
- 未填、后增字段在旧工单无答案、已删除字段在新工单不存在时，单元格为空，不写“未填写”“—”或虚构内容。因数据损坏无法解析不等于未填。
- 图片／视频按F07导出完整URL，不嵌入媒体。同字段多附件在一个单元格内逐项换行，不拆工单行，不丢失链接。
- 表头及长文本可换行，首行冻结，列宽便于阅读；显示样式不得截断实际保存值。字段内容、列数或其他限制导致Excel无法完整承载时整次报错，技术评审核实可承载范围，不静默裁切。
- 文件名为`用户工单_<模板名>_<状态标记>_<日期范围>_<T0时间戳>.xlsx`。状态标记为“处理中”“已完结”或“全部状态”；日期范围为“全部日期”或`YYYYMMDD-YYYYMMDD`；时间戳为北京时间`YYYYMMDDHHmmss`。模板名中的文件系统非法字符替换为下划线，不改变Excel字段标题或模板原名。
- 文件名示例：`用户工单_支付反馈_已完结_20261101-20261103_20261126143000.xlsx`。同秒生成结果仍须绑定各自独立操作，不凭文件名判断为同一结果。

### F06：历史字段、重名及删除重建

历史字段规则是对导出兼容性的规定，不以新增模板编辑、停用或删除功能为前提。

1. 以模板内稳定字段身份关联答案，禁止按当前标题或列位置匹配。字段改名或移动但身份不变仍为同一列；删除后重建即使标题一致，也视为不同字段，不合并旧答案。
2. 当前字段先按T0配置顺序列出；其历史答案输出到同一身份的列。方案设计：表头使用T0当前标题，答案使用当次实际填写内容，模板历史改名不追溯改写答案。
3. 历史已删除字段接续在全部当前字段后。方案设计：使用该模板可恢复的完整历史字段清单，不仅取本次命中工单有值的字段；按字段首次出现的模板版本先后、同版本原顺序排列，仍相同时用稳定字段标识排序。历史列使用删除前最后可恢复标题。
4. 方案设计：历史列表头附加“（历史已删除）”；字段标题相同、与基础列同名或处理后仍重名时，为冲突字段附加稳定字段标识以区分，基础四列表头不改。例如当前“联系方式”和历史“联系方式（历史已删除）”；两个历史同名字段分别为“联系方式（历史已删除，字段H1）”“联系方式（历史已删除，字段H2）”。标题主文案保留，不把两字段合并成一列。
5. 原字段有答案则填写对应列；未提交该字段则空。字段类型、选项标题采用提交时可恢复信息解释答案，不能将旧单选标识直接当成当前新选项的答案。
6. 若历史清单、字段身份、顺序或选项文本缺失，无法保证正确对应，则阻止生成并提示“历史表单数据不完整，暂无法完整导出，请联系管理员处理”。研发核实恢复方案后重试；不凭相同标题合并、不静默丢列或将损坏值留空。技术评审确认既有数据是否满足，不承诺未核实的历史恢复能力。

### F07：图片、视频链接

- 对每条工单、每个附件字段，导出其实际成功提交的全部附件URL，按提交保存顺序逐项换行。保持工单—字段—附件关系，不能串工单、串字段或只保留首个附件。
- URL须完整、可复制并直接访问对应媒体；不输出附件ID、仅后台详情页或需登录的地址。单元格有多个URL时，至少每条都可完整复制访问，不依赖Excel把整格识别成一个超链接。
- 持有链接即可访问，不校验后台登录、工单归属或组织权限；该规则为本需求明确确认的附件访问要求，不扩展为Excel文件及工单详情公开。
- 不复用下载后立即失效的短时后台登录地址，不新增用户可选的过期时长，不承诺永久保存。无鉴权链接实现及资源保存期限由技术评审明确；若无法满足已确认的免登录访问，列为实现阻塞，不擅自改成登录后查看。
- 方案设计：生成时发现附件记录存在但无法得到对应的有效URL、资源已不可用或映射错误时，整次导出失败并提示附件异常，不把有附件伪装为空值。暂时生成或访问故障允许修复后重试，不用其他附件代替。
- 文件生成后附件仍按实际资源生命周期存在。后续资源删除或故障时，访问端应明确反馈不可用；不跳转其他附件、不要求新增后台登录来掩盖链接错误。导出快照保证引用对应性，不保证资源永久在线。

### F08：生成、下载、异常与恢复

方案设计：在P02内完成本次操作，不新增任务中心及历史文件列表。

| 阶段／场景 | 界面与行为 | 数据保留及恢复 |
| --- | --- | --- |
| 选择条件 | 展示目标模板、状态、日期，提供取消、确认导出 | 取消不生成；重新打开恢复默认值 |
| 校验失败 | 对应控件提示缺状态、缺日期或区间错误 | 保留输入，修正后确认 |
| 范围校验／生成中 | 显示“正在生成Excel，请稍候”，禁用条件、确认与关闭，防止同次意图重复创建；不展示虚构百分比 | 不改写模板或工单；失败后解锁。页面意外离开不承诺本地保存或跨会话找回结果 |
| 空数据 | 显示“暂无符合条件的工单”，不进入成功态 | 保留条件，可调整重试或取消 |
| 超过上限 | 展示N、L及缩小范围提示，不生成文件 | 保留条件，可修改后再次确认 |

| 身份失效／失去权限 | 停止生成结果获取与下载，不再展示已失去访问权限的缓存内容 | 按现有登录恢复或返回可访问页面；恢复后重新校验，不自动下载 |

- 生成成功不等于文件已在本地保存；浏览器拦截下载时保留下载按钮，用户可重试，不虚报本地保存成功。
- 页面刷新／意外关闭后重新进入按F01重新选择模板并按默认条件开始，不增加历史任务恢复承诺。服务端生成产物的清理、结果保留时长及查询方式由技术评审明确，不构成用户可配置功能。

## 6. 数据定义与一致性

| 对象／口径 | 定义 |
| --- | --- |
| 模板关系 | 稳定模板身份，不靠模板标题匹配 |
| 用户提交来源 | 用户主动提交的工单；移交、完结不改变来源，客服关联用户不等于用户提交 |
| 提交时间 | 成功提交发生时间，用于日期筛选及排序；展示北京时间 |
| T0 | 本次有效确认被服务端接受的数据截至时点；不是页面打开时间或文件完成时间 |
| 当前状态／负责人 | T0快照；负责人不是模板默认人、曾经处理人或管理员完结人 |
| 当前表单列 | T0模板配置字段身份及顺序，标题按T0当前名称 |
| 历史列 | T0前该模板已删除字段，按F06历史清单及稳定身份排列 |
| 答案 | 用户当次提交的实际内容及选项可读文本，历史答案不被新配置覆盖 |
| N | 同一T0、同一组合条件及权限下去重工单数，等于成功文件数据行数 |
| L | 本次执行生效的研发配置上限，暂定5000；仅比较N，不计表头或附件数 |

## 7. 数量、文件与结果校验要求

- 真实系统应验证N=0、1、L、L+1；L暂定5000时5000可成功、5001整次拦截。更改配置后，新操作使用新上限且提示同步，前端提示不能一直写死5000。

## 8. 权限、组织隔离与数据质量

1. 发起、生成结果获取及下载均校验当前管理员身份、当前组织和目标模板权限，文件名、操作标识或下载地址不能成为绕过校验的依据。普通客服及其他组织不可通过直接请求获取Excel。
2. 下载时权限仍须有效。管理员退出、角色降级或切换组织后，旧页面／旧结果不可继续获取；客户端清理越权结果展示，服务端拒绝越权下载，不因本地仍有按钮而放行。
3. 已合法下载到本地的Excel不承诺远程撤回。附件链接按本需求公开访问要求执行，即使打开者无后台身份也能访问；不把Excel下载鉴权逻辑套到导出的媒体URL上。
4. 与FR-wenkf-002的关系：旧PRD“本次不做导出”不阻止本独立需求；其原附件随工单权限控制的规则，不能覆盖FR-wenkf-004已确认的导出媒体免登录规则。本次只规定导出媒体URL的访问语义，不将后台工单详情、原查看入口、Excel文件或其他资源整体公开，也不修改旧档案。若现有资源实现无法区分访问入口，研发应提出满足本次要求的方案，不能无说明地取消免登录要求。
5. 历史记录的来源、模板关系、字段身份、选项文本、答案及附件引用必须可验证。无法判断的数据不猜测归类；数据损坏不能伪装为空白或无记录，按F04／F06／F07失败反馈处理。
6. 生成过程不修改工单状态、负责人、提交时间、表单答案或模板。重试、超量及失败也不产生新的工单或处理记录。
