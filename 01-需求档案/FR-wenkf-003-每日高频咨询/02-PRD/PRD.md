## 2. 背景、目标与范围

### 2.1 背景与目标

运营及管理人员需要了解用户集中咨询的问题，以及人工客服实际使用的回复方式。系统每日自动分析当前组织人工客服与用户聊天文本，生成前一北京时间自然日的高频咨询Top 10及对应回复话术；在数据统计页展示昨日结果，并逐日保存供历史回查。

用户无需主动生成，也不参与审核发布。查看历史读取保存结果，不在每次查看时重新生成。

- 机器人对话接入，工单内容、图片及语音分析，知识库补充回答。
- 人工审核、人工编辑或删除总结，手动重生成入口。
- 自动回复、快捷回复应用、知识库写入等话术其他应用方式。
- 上线前历史补算、多日合并总结、实时总结、按客服个人排行及跨组织总榜。
- 导出、消息推送、模型配置管理页面、独立任务管理入口。

| 页面编号 | 页面/区域 | 既有情况及本次变更 |

### 4.2 正常流程

1. 自然日结束 → 系统按组织读取该日聊天文本 → 归并问题、归纳客服实际回复 → 按去重会话数排序取最多10类 → 完整保存结果 → 次日02:00前可查看。
2. 有权限账号进入当前组织P01 → 查看昨日日期及各问题对应话术 → 点击历史入口。
3. P02默认查看最近可回查日期 → 选择某个日期 → 阅读该日完整总结 → 返回P01。

无有效咨询保存无数据结果；读取不完整或生成失败走失败流程；页面查询失败仅影响本次读取，不改变生成状态。

## 5. 功能详细规则

### F01：昨日高频咨询模块

**前置条件：** 账号有数据统计权限，当前组织有效。

- 进入P01即查询前一北京时间自然日的保存结果；标题为「昨日高频咨询」，明确显示所属日期，日期格式YYYY-MM-DD。
- 无用户输入条件，昨日日期由北京时间当前日期减1天得出，不受数据统计页其他筛选条件影响（方案设计）。
- 最多展示10项，每项包含排名、问题描述及对应回复话术。话术紧随所属问题，长内容可展开阅读全文，不静默截断关键信息（方案设计）。
- 右上角「历史高频咨询」进入P02。查看无需再次触发AI调用。
- 方案设计：页面不增加会话数统计列，频次仅用于内部排名；展示日期、生成状态，成功时展示生成完成时间并标注北京时间。
- 今日、前天或任务执行日不得替代昨日；昨日未成功时展示其真实状态，不能回退展示前天成功结果冒充昨日。
- 功能上线当天尚无可回查日期时，提示「首份总结将于上线次日02:00前提供」，不展示上线前一天内容（方案设计）。

### F02：历史高频咨询

**前置条件：** 账号有数据统计权限，目标日期属于当前组织可回查范围。

以下页面交互为方案设计，供本PRD整体评审：

- P02标题「历史高频咨询」，提供返回数据统计页路径。默认日期为昨日；上线当天无可回查日期时展示首次生成说明。
- 采用单日日期选择，不提供区间汇总；日期范围为上线日到昨日（均包含）。今日、未来、上线日前不可选择；直接请求非法日期同样拒绝，不发起补算。
- 日期快捷列表按所属日期倒序，每页20个日期，显示各日生成状态；覆盖上线日至昨日的应有日期，无记录的日期标记待生成，不隐藏失败日期。分页仅改变日期列表，不合并多日内容。
- 点击日期或选择器选中合法日期立即查询并更新单日详情；不设额外查询按钮。选择器定位到该日期所在列表页；翻页后选中该页首日，展示其详情。无效输入提示并保留原有效日期和结果。
- 刷新保留当前日期和列表页，重新查询日期状态及详情。返回P01后按实时昨日重新查询。
- 每日详情与P01使用相同的保存结果及话术缺失文案；不因查看历史重新调用AI。
- 整个日期范围未开始时展示空历史；某日无咨询、待生成、失败分别展示相应状态。目标不存在且不在合法日期范围时提示不可访问；范围内缺失记录按待生成处理，不误报无咨询。

### F03：数据范围与自动生成

**触发：** 系统每日凌晨自动执行，与用户是否打开页面无关。具体启动时刻、模型供应商和任务调度由研发设计，不在本文规定接口路径或性能参数。

1. 确定组织和总结所属日期D，按消息发送时间截取北京时间区间`[D 00:00, D+1 00:00)`。
2. 仅纳入该组织人工客服与用户的聊天文本；排除工单内容、图片、语音及机器人数据。不对图片OCR、语音转写或工单读取后再混入输入。
3. 会话未结束也可纳入；不按会话开始、接待开始或结束时间整体归日。不能沿用FR-wenkf-001的接待日期归属规则。
4. AI归并统计日出现的问题；客服话术也仅从同日文本中归纳，不能读取前日或次日聊天补全答案。
5. 按F04统计排名，按F05生成话术，校验完整性后按F06保存。
6. D+1日02:00前结果应已可查看；无有效咨询则同样在该时间前保存无数据结果。02:00时仍未成功完成属于可用时间目标未达成，即使之后补齐，也不能将超时描述为按时成功。

方案设计：输入为空可直接判定无数据；存在文本但无法识别有效咨询时，仅在数据读取完整且分析成功的前提下判定无有效咨询。读取不完整、模型超时、不可解析或结果校验失败均不能判为无数据。部分结果不对外作为成功发布。

### F04：问题归并、频次与排名

**已确认规则：**

- 表达不同但属于同类的问题合并为一类。频次为统计日涉及该类别的去重会话数，不是用户人数、消息条数或客服接待次数。
- 去重范围为同组织、同日、同会话、同问题类别。同一会话同类反复提问只计1次；另一会话出现同类问题再加1。
- 按频次降序取前10类；不足10类按实际数量展示，不虚构问题。

**方案设计：**

- 一个会话涉及多个不同类别时分别计入。各类别会话集合可重叠，各类别频次之和不代表组织去重总会话数，不新增合计指标。
- 沿用现有会话身份；同一会话转接多名客服不因客服变化重复累计。研发须核实现有转接后的会话标识，不自创按客服拆分的会话口径。
- 并列频次按本次生成结果内的固定唯一类别次序升序排列，保存最终排名；同一已保存结果多次读取时不重新排序。次序生成规则由研发落实并可验证；不承诺不同模型重试产生完全相同的语义类别。
- 原始会话引用与分类依据须能在内部验证会话去重和来源归属，不要求新增会话明细下钻页面或公开原聊天。

### F05：对应回复话术

- 每类问题仅归纳客服实际回复，禁止知识库补充或AI自行编造。生成完成后直接展示，不设人工审核、发布操作。
- 同一统计日内的问题与相关回复须正确关联，不能把同会话其他问题的回复自动归给当前问题，也不能跨问题、跨组织或跨日期取用话术。
- 方案设计：保留回复适用条件、限制和分支，不虚构承诺、时间或处理结果；不同条件的回复分别表达，不拼为统一承诺。
- 方案设计：无可归纳的对应客服回复时，保留问题及排名，话术显示「暂无可归纳的客服回复」。例如当日23:59提问、次日00:01才回复，当日话术不得使用次日回复。
- 方案设计：用户姓名、账号、手机号等个人信息不得原样写成通用话术，使用去除或泛化后的表述；不能因处理个人信息而改变业务限制。
- 当天仅有对前日问题的回复而没有当天实际出现的问题时，不凭回复或统计日外文本推断一个新咨询类别（方案设计）。

### F06：保存、上线起点与状态流转

**已确认：** 从功能上线起逐日保存，不补算上线日前历史。首份总结在上线次日02:00前提供，覆盖上线当天完整自然日，包括当天上线时刻之前已有的聊天文本。未指定保留期限，不自行自动清理。

**方案设计：** 每个组织、每个所属日期至多有一份对外可见记录。成功结果为当次生成的历史保存内容，读取时不随现有会话状态变化重算；不因客服转接、离职或新消息出现改变旧结果。具体迟到消息接入、时钟及任务并发处理需保证成功结果稳定，不自动引入历史补算功能。

| 状态 | 判定与展示 | 后续路径 |
| --- | --- | --- |
| 待生成 | 合法日期尚无完成记录或等待执行，展示日期和「待生成」 | 自动开始后转生成中 |
| 生成中 | 正在读取或分析，展示日期和「生成中」 | 成功、无数据或失败 |
| 成功 | 问题、排名和话术完整校验并保存 | P01/P02读取同一结果，不由访问触发重算 |
| 无数据 | 完整读取、成功判断无有效咨询，保存完成状态，展示「当日暂无可总结的咨询」 | 作为该日结果历史回查 |
| 失败 | 读取、分析或结果保存失败，不展示部分成功内容 | 后台自动重试可转生成中，成功后补齐同一日 |

生成中是业务处理状态；页面加载中只是查询过程，二者独立。查询失败不把保存记录改为生成失败。

- 重复任务和并发重试不能产生重复可见记录，单日内容须完整保存后对外可见。
- 失败不能覆盖已有成功或已完成无数据结果，成功后的重复任务不自动重新发布不同内容。
- 自动重试沿用原组织、原所属日期和时间范围，不将补齐日当成总结所属日。次数、间隔、内部告警及故障处理方式由研发评审确定，不新增用户通知或任务管理页面。
- 02:00后仍待生成、生成中或失败时，保留真实状态并补充「未按计划完成」，不能无期限显示为按时处理（方案设计）。

### F07：权限、查询与刷新一致性

- 每次进入P01/P02、选择日期、分页、刷新均校验数据统计权限和当前组织。不得通过替换组织或日期参数读取其他组织记录。
- 组织切换立即撤下原组织内容、取消原查询的展示资格，重新计算可回查日期并查询新组织；旧组织晚返回响应不得显示。
- 权限撤销或登录失效一经系统识别，立即撤下不可访问内容；请求返回无权限时不保留旧内容。恢复现有登录或权限后重新查询。
- 方案设计：模块提供「刷新」；历史页提供「刷新」。手动刷新只读取状态与保存结果，不调用AI、不提供重新生成。
- 方案设计：同日期刷新时可保留已成功内容并明确显示刷新中；刷新失败说明「更新失败，当前为上次读取结果」，可重试。切换日期或组织时撤下旧详情，显示目标日期加载态，不能用旧内容冒充新结果。
- 仅当前组织、当前日期及最新请求结果可生效。问题、话术、排名、状态和生成时间使用同一完整结果，不分片混用两个版本。
- 方案设计：不做定时轮询；跨北京时间零点，打开页面或执行任何查询/刷新时重新计算昨日及日期上限，清除P01旧日期内容。已打开页面未重新读取时保留明确所属日期，不能把原内容无日期标成新昨日。

### F08：异常、空态与恢复

| 场景 | 反馈及数据保留 | 恢复方式 |
| --- | --- | --- |
| 首次查询加载 | 目标日期及加载占位，不展示其他日结果 | 查询成功后替换 |
| 上线当天尚无历史 | 首份总结次日提供说明，无上线前日期 | 次日刷新 |
| 无有效咨询 | 「当日暂无可总结的咨询」，不补齐10类 | 可回查该日保存状态 |
| 待生成/生成中 | 所属日期及真实生成状态，超时增加未按计划完成说明 | 刷新查看最新状态 |
| 生成失败 | 「生成失败，请稍后刷新查看」；不显示原始模型错误或个人信息 | 系统自动重试，用户刷新仅查询 |
| 查询失败 | 「加载失败，请重试」；同日期刷新可保留上次读取结果并标注 | 重试本次读取，不重新生成 |
| 日期输入不合法 | 提示可选范围，保留上次有效日期与结果 | 选择合法单日 |
| 无权限/组织不符/目标不可访问 | 不展示内容及缓存，不泄露其他组织记录存在与否 | 返回有权限页面或恢复原身份 |

## 6. 字段与数据口径

### 6.1 业务对象

以下为业务数据要求，不固定数据库结构或接口字段名。

| 对象/字段 | 定义与约束 | 页面使用 |
| --- | --- | --- |
| 组织 | 输入及保存结果的所属组织 | 由当前组织上下文决定，不可跨组织查询 |
| 所属日期 | 北京时间自然日，格式YYYY-MM-DD；不是执行日期 | P01/P02明确展示 |
| 输入时间边界 | 消息发送时间含当日00:00、不含次日00:00 | 用于生成，不按会话生命周期归日 |
| 会话身份 | 沿用系统会话定义，转接不重复统计同一会话 | 内部去重，不新增下钻 |
| 问题类别 | 对当日同类问题语义归并后的描述 | 每项展示 |
| 类别频次 | 该类别涉及的去重会话数，正整数 | 内部排序，不新增频次数值展示（方案） |
| 最终排名 | 1至实际类别数量，最多10，唯一连续 | 展示顺序，保存后稳定 |
| 回复话术 | 对应问题的同日实际回复归纳；缺失时有明确标识 | 显示归纳或缺失提示 |

## 7. 数据质量与实现约束

- 生成前确认组织范围、输入时间范围及读取完整性。读取失败、缺失或模型输出不符合结果规则时，不得假报无咨询或成功。
- 问题须来自当日用户咨询，话术须来自关联的同日客服回复。模型不能根据聊天中要求改变指令的文本越过统计范围或编造结论。
- 模型调用只使用本次必要聊天文本及其关联信息，不附带其他组织、工单或统计日外文本。具体供应商、调用协议及信息处理实现由研发评审，不声明未确定的模型能力已实现。
- 对保存结果验证类别不重复、频次为正整数、排名最多10且连续、问题话术对应；话术缺失是合法状态，不强制编造内容使校验通过。
- 历史读取不调用模型；当前客服状态、会话结束、后续回复等不追溯改写已保存结果。实际输入缺失、历史数据可得性及消息延迟需要评审核实，不能静默改成缩短统计时段。
- 不在本文指定数据库、接口路径、模型名称、吞吐或响应时延数字；02:00前可查看是已确认业务目标，须据此完成任务时序设计。
