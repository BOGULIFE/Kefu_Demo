## 2. 背景、目标与范围

### 2.1 背景与目标

新增用户主动填写表单提交反馈的工单渠道。管理员为不同反馈类型配置表单及默认处理人，用户选择类型并提交后由对应客服处理。通过工单记录和处理结果，用户可回查自己的申请与处理结论。

图1为现有“工单处理”列表，已有搜索标题／工单号／用户ID、指派给我、全部状态、查询和创建工单；表格已有问题与编号、状态、优先级、当前负责人、下次反馈时间、处理结果及详情操作。图2为H5搜索、八个问题快捷图标、常见问题内容及底部人工客服入口。

现有客服创建工单与新增用户提交工单进入同一个业务列表，共用详情框架和处理入口，避免两个地方处理。“同一列表”不规定数据库必须物理合表。后续截图补充了待接收、处理中、已完结的右侧详情抽屉、时间线，以及完结弹窗。详情沿用抽屉承载；截图中的旧状态名称为“待接收”（此前文档称待接取，两者指同一旧接收环节，不并列新增状态）。现有创建表单仍未提供，不推定其完整交互。

### 2.2 本次范围

- 管理后台：扩展现有统一工单列表及详情，增加来源列和来源筛选，保留搜索、归属、状态、创建入口；支持用户提交工单移交、填写结果并完结。
- 管理后台：创建工单类型，即表单模板；配置一个默认处理人、六类字段及必填规则。
- H5：新增“工单记录”“提交工单反馈”卡片；类型选择、动态表单提交、本人历史列表与详情、完结结果展示。

### 2.3 本次不做

不为用户提交工单新增接取或待接取状态；客服创建工单保留既有流程。不新增用户回复／追加资料、撤回、重开、催办、通知推送、SLA、自动升级、多处理人、批量操作、导出、统计报表和其他端。不改变既有工单流程，也不默认把用户工单纳入FR-wenkf-001统计。

模板编辑、停用、删除及默认处理人变更不是当前已确认范围，本版不以隐藏操作形式加入；相关历史兼容约束见第8节。保留已有标题／工单号／用户ID搜索，不新增长文本全文搜索、复杂日期筛选或自定义列表字段。

## 3. 角色与权限

下表规定用户提交来源的权限。客服创建来源继续沿用既有权限；统一列表先分别按来源确定可访问集合，再与查询条件取交集，不因管理员、来源切换或共用详情而自动改写旧权限。

| 能力 | 管理员 | 普通客服 | H5用户 |
| --- | --- | --- | --- |
| 查看全部用户工单 | 允许 | 不允许 | 不允许 |
| 查看指派给我的工单 | 允许 | 允许，唯一业务范围 | 不适用 |
| 查看后台工单详情及附件 | 全部可访问工单 | 仅当前指派给自己的工单 | 不允许进入后台 |
| 移交、完结 | 全部处理中工单 | 仅当前指派给自己的处理中工单 | 不允许 |
| 创建模板及配置处理人 | 允许 | 不允许 | 不允许 |
| 选择模板并提交 | 不作为后台能力提供 | 不作为后台能力提供 | 允许 |
| 查看H5记录、详情及处理结果 | 不适用 | 不适用 | 仅本人提交的工单 |

管理员在统一列表可查看两类来源中其有权限的全部工单；普通客服按已确认方案仅查看指派给自己的用户工单，客服创建来源遵守既有权限约束。

“全部”为当前业务可访问范围，不表示跨组织。方案设计：沿用现有账号、角色及组织边界；不新增跨组织查询、跨组织指派或独立登录体系。若现有系统没有组织概念，则按现有业务隔离边界实现，不为本需求新建组织体系。

权限应覆盖列表、详情、附件访问和写操作，不能只隐藏按钮。针对用户提交来源，普通客服移交后即失去该工单查看与处理资格，即使曾经处理过也不保留历史查看权限；管理员不受当前处理人限制。H5身份失效时按现有身份恢复方式处理，不得将用户绑定为其他身份继续提交或查询。

## 5. 主流程与状态

### 5.1 用户提交来源主流程

1. 管理员创建工单类型，配置表单字段、必填规则和一个有效客服处理人，保存成功。
2. 用户从H5“提交工单反馈”选择该类型，填写对应表单并完成附件上传。
3. 提交校验通过后，创建工单、保存提交内容、自动指派模板处理人，状态直接为“处理中”。
4. 客服从“指派给我的工单”打开详情处理；管理员可从全部列表处理。需要其他客服处理时执行移交，无接取步骤。
5. 有权限的操作者填写处理结果并完结。提交用户在工单记录详情查看“已完结”及结果说明。

### 5.2 用户提交来源状态机

| 原状态 | 事件与条件 | 结果 |
| --- | --- | --- |
| 未创建 | 有效身份、模板、处理人、表单及附件校验通过，提交成功 | 创建一张工单，处理中，归属模板默认处理人 |
| 处理中 | 有权限的操作者移交给其他有效客服 | 仍为处理中，当前处理人变更 |
| 处理中 | 有权限的操作者填写有效处理结果并完结 | 已完结，保存完结人、时间、结果 |
| 已完结 | 再次移交或完结 | 拒绝修改，提示当前已完结 |

“提交中”“上传中”“加载中”仅为界面过程，不是工单业务状态。提交失败且未创建工单时，不产生历史记录。移交不新增工单、不改变提交人、提交时间、表单内容和工单编号。

方案设计：用户提交来源的已完结工单只读，不支持重开或修改结果；保留提交、移交、完结操作记录，用于后台核查，不新增独立审计模块或用户端流转轨迹。

### 5.3 两类来源的状态兼容

| 场景 | 客服创建 | 用户提交 |
| --- | --- | --- |
| 创建 | 现有“创建工单”流程及初始状态 | 模板校验成功后直接处理中 |
| 移交 | 保留既有移交和接取规则 | 更新负责人，保持处理中，无需接取 |
| 完结 | 沿用既有处理结果及权限规则 | 必填处理结果，提交用户在H5可见 |
| 列表与详情 | 同一列表及框架，显示既有内容和合法操作 | 同一列表及框架，显示模板答案和合法操作 |

统一状态筛选兼容待接取、处理中、已完结及现网其他已存在的状态；不为用户提交生成待接取。既有材料提到客服工单待接取，但截图仅能证实有已完结记录，研发须核实当前旧流程并保持兼容。以下F03、F04的具体状态转换与必填公开规则只用于用户提交来源；客服创建工单的按钮和操作校验按既有逻辑执行。

## 6. 管理后台详细规则

### F01：统一列表、来源与组合查询

- 只使用现有“工单处理”菜单，不另设用户工单列表。保留“创建工单”，仍进入既有客服创建流程，不强制选H5模板。管理员增加“工单类型配置”入口，普通客服不显示。
- 来源选项：全部来源／客服创建／用户提交，默认全部来源。来源由创建渠道写入，移交、完结不能修改；旧后台创建记录归入客服创建，不因缺少新字段消失。
- 归属默认沿用图1“指派给我”；管理员可切换全部工单，普通客服不新增全部权限。“指派给我”按当前负责人判断，不是曾处理过；用户工单已完结后保留最后负责人。
- 搜索保留标题、工单号、用户ID；方案设计：去除首尾空白，标题包含匹配、工单号及用户ID精确匹配，三者任一匹配即可。若现网匹配规则不同，优先保持原规则并在评审同步，避免静默改变旧搜索。
- 搜索、归属、状态及来源条件之间取交集；选择或输入后点击“查询”生效并回到第一页。条件尚未提交时不改变结果，分页继续使用上次成功查询条件。状态默认全部，选择待接取+用户提交应返回空结果，不伪造映射。
- 保留问题与编号、状态、优先级、当前负责人、下次反馈时间、处理结果及查看详情列；新增来源列。用户提交工单以模板名称作为标题，不在标题下方重复展示类型；客服创建沿用原规则。
- 用户提交标题直接使用模板名称，不拼接用户ID，不要求用户输入标题，也不取首个答案；用户ID保留在原编号辅助信息中。用户工单默认普通优先级，H5无优先级选择；未设置下次反馈时间显示“—”，不新增调度提醒；未完结结果显示“—”，长结果摘要展示并可进详情看全文。
- 方案设计：每页20条，按创建时间倒序（用户提交使用提交时间），相同时间按稳定唯一顺序。刷新保留成功生效的条件并回第一页；不自动清空来源或混入越权记录。
- 初次加载显示加载态；无匹配记录显示空态，失败显示错误和重试，不以空列表冒充失败。只接受最新查询结果；返回列表保留已生效条件并重新校验权限，越界页回有效页。

### F02：工单详情

- 两类来源共用基础信息、问题内容、处理区域和操作记录框架。基础信息明确显示来源，客服创建显示原问题描述及附件，用户提交显示下述模板答案，不为客服工单捏造模板字段。
- 根据来源、状态及权限决定按钮：用户提交处理中支持移交与完结且无接取；客服创建保留现有接取等合法操作。原内部备注／流转记录不自动映射为用户可见结果。
- 对用户提交来源，展示工单编号、提交用户、类型、提交时间、当前处理人和状态；按提交时字段顺序展示字段名称及答案。选填未填写显示“未填写”。
- 单选展示所选项，多选展示全部所选项；图片可预览，视频可播放。媒体加载／播放失败提示重试，不将失败文件显示为用户未上传。
- 已完结展示处理结果、完结时间及后台可见的完结人。H5不默认展示客服个人账号信息。
- 方案设计：后台显示操作记录，包括提交及初始指派、移交前后处理人／操作者／时间、完结人和时间；不支持用户修改已提交内容或后台篡改原始答案。
- 详情进入或刷新时重新校验权限和最新状态。无权限、记录不存在或不在当前范围时显示不可访问，不继续展示缓存内容和附件；允许返回列表。

### F03：移交

前置条件：来源为用户提交、状态为处理中，管理员或当前处理客服可操作；客服创建来源保留既有规则。

1. 点击移交，选择一个其他客服；候选范围为同一业务隔离范围内、具备处理资格且账号有效的客服。在线／离开状态不作为账号有效性的替代条件。
2. 当前处理人不可选择，未选择接收人不可确认；本版不增加移交原因必填字段。
3. 确认前展示目标客服；确认中防止重复操作，可取消未提交的移交。
4. 成功后当前处理人更新，状态仍为处理中。管理员刷新详情；普通客服因失去归属权限返回本人列表并提示移交成功，旧详情和附件不可继续访问。
5. 接收客服下次进入／刷新本人列表可见该工单，直接处理，无需接取。不新增实时推送。
6. 接收人失效、权限变化、已被他人移交或已完结时拒绝当前操作，提示刷新后重新查看；不覆盖他人已成功修改。常规失败保留目标选择并可重试，重试仍需校验最新条件。

### F04：完结

前置条件：来源为用户提交、状态为处理中，管理员或当前处理客服可操作；客服创建来源保留既有规则。

1. 点击完结，复用新截图中的“完结工单”弹窗：处理结果为“已解决／未解决／转需求”单选，默认已解决；依次填写内部处理结论、处理依据／验证记录、面向用户的结果说明，三个区域均必填。
2. 三项说明去除首尾空白后均不能为空；方案设计每项纯文本最多2000字符，不支持附件或富文本，错误定位至对应区域。“面向用户的结果说明”提示“这段内容会展示给用户，请使用易懂的语言”；内部处理结论与验证记录仅后台可见。按钮沿用“取消／确认提交”。处理结果三选项是完结分类，不新增工单状态；选择未解决或转需求仍为已完结，本次不扩展自动创建产品需求的联动。
3. 确认成功后，一次性保存已完结状态、处理结果分类、内部结论、验证记录、面向用户的结果说明、完结时间和完结操作者；管理员代为完结不改变当前处理人。
4. 后台详情显示结果并隐藏移交、完结操作；H5下次进入／刷新记录和详情可见已完结及结果。
5. 失败时不显示成功，保留结果输入供重试。若最新状态或权限变化，先反馈并重新加载可访问信息；普通客服已失去权限时不允许继续提交结果。
6. 多人同时完结仅接受一次有效结果；失败方不得覆盖成功方结果。请求响应丢失时先核实最新状态，再决定是否重试。

### F05：创建工单类型与处理人

- 从现有“工单处理”页内进入“工单类型配置”，仅管理员可配置及创建；模板服务H5提交，不强制用于旧客服创建表单。方案设计：P03展示模板名称、默认处理人、字段数量、创建时间；提供创建入口，无数据时提示创建。
- P04配置模板名称、一个默认处理人及字段。名称作为H5反馈类型名称，不另建类型与模板两套对象。
- 方案设计：名称去首尾空白，1—50字符，同一业务范围内名称不可重复；处理人必须为有效且具备处理资格的客服，必须且只能选择一人。
- 至少配置一个有效字段后可保存；保存时校验名称、处理人及全部字段配置。保存中防重复，失败保留已填配置，成功返回模板列表。
- 方案设计：保存成功的有效模板直接供H5选择，不额外增加发布审批或草稿状态；未成功保存不对H5展示。
- 模板处理人临时离线仍可指派；账号被停用、删除或失去处理资格时，不得将新工单交给该无效账号，也不默认随机分配或转给管理员。H5提示类型暂不可用并保留填写内容；管理员通过现有账号治理或另行确认的模板维护方案恢复。

### F06：字段配置及输入

方案设计：每个模板1—30个字段。字段名称必填、去首尾空白后1—50字符，同一模板内不重名；字段具有稳定标识，不能以名称或排列位置替代标识。管理员可在创建时增删字段、调整顺序、选择类型及切换必填。未保存前的调整不影响已创建模板。

| 类型 | 模板配置 | H5输入与校验方案 |
| --- | --- | --- |
| 文本 | 字段名称、是否必填 | 单行纯文本，最多200字符；必填时去首尾空白后不能为空 |
| 单选项 | 名称、是否必填、选项 | 无默认选中，最多选一个；必填时必须选一个有效项 |
| 多选项 | 名称、是否必填、选项 | 无默认选中，可选多个且不重复；必填时至少一个有效项 |
| 图片 | 名称、是否必填 | 每字段最多9张，JPG／JPEG／PNG，单张不超过10MB；必填至少一张上传成功 |
| 视频 | 名称、是否必填 | 每字段最多1个，MP4，单个不超过100MB；必填至少一个上传成功 |
| 长文本 | 名称、是否必填 | 多行纯文本，最多2000字符；必填时去首尾空白后不能为空 |

单选／多选配置方案：每字段2—20个选项，每项去首尾空白后1—50字符，同字段内选项不可重复；空选项不能保存。文本及其他非选项字段不保留无效选项配置。切换字段类型导致已配置内容丢失时先提醒管理员。

上述数字、格式均为本PRD方案参数，需产品／研发评审媒体存储及H5兼容性后定版，不宣称现有系统已支持。前后端须使用一致规则；字符数按用户可感知字符计算，附件边界以明确字节规则实施（本方案1MB=1024×1024字节）。不满足限制的文件不得进入提交内容。

## 7. H5详细规则

### F07：入口与类型选择

- 在八个快捷问题图标下方、“常见问题”内容区上方增加“工单记录”“提交工单反馈”两张卡片；方案设计为横向排列。保留原搜索、问题图标、常见问题内容及底部“人工客服”按钮。
- 点击“工单记录”进入P09；点击“提交工单反馈”进入P06。身份识别沿用现有客服页面，身份不可用时先按原系统方式恢复，不静默创建新身份。
- P06展示当前用户业务范围内可提交模板的名称，点击一个进入P07；不要求用户选择处理人。
- 加载时显示加载态，失败支持重试；无有效模板显示“暂无可提交的反馈类型”，可返回客服首页。
- 方案设计：类型列表按创建时间倒序稳定排列，无类型搜索。表单中返回类型选择后改选其他模板，若已有填写或附件先确认放弃，确认后清空旧模板内容，避免串填；取消则留在原表单。

### F08：表单填写、上传与提交

1. 进入P07展示类型名称及对应字段，顺序与模板一致，必填项明确标记；不默认代填选项。
2. 图片和视频从设备选择，支持移除已选文件；图片可预览、视频可尝试播放。上传中逐项显示进度／状态；失败显示重试或移除入口。选填文件若仍在上传或失败，须完成上传或移除后再提交，不能静默丢弃。
3. 纯文本按文本展示，不能执行用户输入的HTML或脚本。单／多选只能提交当前模板的有效选项，不接受伪造项或其他模板附件。
4. 点击提交校验全部字段、附件、身份、模板与处理人有效性。错误提示具体字段并定位首个错误，保留其他内容。前端校验不能替代服务端校验。
5. 提交中锁定重复提交与模板切换；成功创建的工单包含当前用户、提交时模板及答案、有效附件、默认处理人，来源为用户提交，直接为处理中；进入统一工单列表，不复制到另一套处理列表。
6. 成功进入P08，显示工单编号、“查看工单”及“返回客服首页”；查看工单进入该工单详情，不自动发起第二次提交。再次主动进入提交入口可创建新申请，本次不按相似内容限制用户重复反馈。
7. 校验或确定未创建的失败保留本次输入并允许修正重试。网络超时且无法确认创建结果时，显示正在核实／重试查询，不能直接提示“提交失败，请重新申请”；同一次提交重试只能得到同一张工单，确认没有创建后才允许继续提交。
8. 方案设计：填写内容仅在当前表单会话内保留，不新增跨设备或长期草稿；离开未提交表单时提醒，刷新、关闭页面不承诺恢复。临时上传不等于工单提交，未提交附件按现有存储生命周期清理，不向其他用户开放。

### F09：记录与详情

- P09仅展示来源为用户提交且提交人为当前身份的工单，包括处理中和已完结；客服在后台为该用户创建的工单即使关联用户相同，也不展示；列表项至少展示类型名称、工单编号、提交时间及状态。
- 方案设计：默认全部状态，可切换全部／处理中／已完结；按提交时间倒序，每次20条，继续加载更多。切换状态重置列表，只接受最新条件的结果；加载更多失败保留已加载内容，支持重试同一页，不追加重复工单。
- 无历史显示“暂无工单记录”，提供提交入口；某状态无记录显示该状态空态。初次失败与空列表分开提示。进入页面或主动刷新获取最新数据，不承诺实时更新。
- 点击进入P10，展示提交时类型名称、工单编号、提交时间、状态、字段及答案；附件支持图片预览和视频播放。未填写的选填项显示“未填写”。
- H5只展示本人主动提交的表单、状态及公开处理结果，不展示内部备注、后台操作记录、旧客服工单结果或仅因关联用户相同的记录。处理中不展示不存在的处理结果；已完结显示完结时间和完整处理结果说明，不仅显示已完结标签。
- 记录与详情均不提供移交、完结、撤回、修改、追加回复或重开；用户不能查询他人工单，替换工单编号或附件地址也不能绕过本人限制。
- 详情刷新失败时明确提示未获取最新状态，不将旧状态标为最新；身份切换／失效、无权限或记录不可访问时清除旧展示，可返回记录或首页。

## 8. 数据定义与一致性

下表除明确描述两类来源的条目外，新增字段和保存规则针对用户提交来源；客服创建的既有数据语义保持兼容。

| 数据 | 定义与约束 |
| --- | --- |
| 工单编号 | 两类来源在统一列表内可稳定区分的唯一标识；沿用已有编号，不重新生成旧工单，用户提交编号与旧编号不冲突 |
| 来源 | 客服创建／用户提交，按实际创建渠道记录且不可由表单篡改；与模板类型分开 |
| 标题 | 客服创建沿用原值；用户提交直接使用模板名称，不拼接用户ID |
| 提交用户 | 提交成功时绑定的现有用户身份，不由表单自填账号决定，不随客服移交变化 |
| 工单类型／模板 | 同一业务对象；提交时保存名称、字段名称／类型／顺序、必填规则及选项与答案的对应关系 |
| 提交内容 | 用户当次成功提交的答案和有效附件引用；提交后只读 |
| 当前处理人 | 创建时为模板处理人，移交后为接收人；已完结保留最后处理人 |
| 工单状态 | 用户提交仅处理中、已完结；客服创建保留现有状态与接取规则 |
| 处理结果 | 完结分类：已解决／未解决／转需求；不是工单状态。用户提交来源在H5展示分类及面向用户的结果说明；客服创建不自动公开 |
| 内部处理结论、处理依据／验证记录 | 完结弹窗两项必填文本，仅后台详情／时间线展示，不进入H5 |
| 面向用户的结果说明 | 完结弹窗必填，对提交用户公开；与已完结状态一起生效 |
| 完结人 | 实际执行完结的后台人员，可与当前处理人不同 |
| 时间 | 提交、移交、完结分别记录成功发生时间；方案设计采用北京时间展示 |

- 成功创建、指派和初始状态须作为一个完整结果对外可见；不出现“已创建但无处理人”的半成功记录。完结状态与结果也不可分开生效。
- 权限、最新状态、当前处理人须在写操作最终生效时再次校验。过期详情发起的移交／完结不允许覆盖新的归属或状态。
- 相同操作的重复请求不能产生重复工单、重复移交记录或覆盖完结结果；具体实现方式由研发确定。
- 若后续增加模板修改能力，历史工单仍按提交时表单展示，不被新字段名、选项删除、字段必填变化或处理人变更追溯覆盖。本版不因此额外开放模板编辑。
- 附件随工单权限控制；用户提交工单移交后，原普通客服不得凭旧链接继续访问，H5用户也不得访问他人附件。管理员可访问的附件仍受业务隔离约束。

### 8.1 历史兼容与展示边界

- 现有后台创建工单归为客服创建；研发须核实历史来源识别、编号及创建时间数据，不能直接把无法识别的记录推定为用户提交，更不能据此公开到H5。
- 上线前后客服创建工单的数量、编号、内容、状态、权限及旧创建操作保持兼容；统一列表筛选合并的是可访问业务记录，不复制工单。
- 用户工单即使经过客服移交、管理员代完结，其来源仍是用户提交；客服创建工单也不会因为关联某用户而成为用户提交。
- 只扩大后台展示范围，不默认扩大FR-wenkf-001统计集合；用户提交的无接取流程不套用旧经手统计。

### 8.2 口径示例

模板“支付反馈”默认处理人为客服A，用户U提交工单T：T立即为处理中，A的“指派给我”可见；U只能在本人记录看到T。A移交给B后，T仍为处理中，A不再有访问权限，B无需接取即可处理。管理员M填写“已核实并完成处理”完结后，当前处理人仍为B，完结人为M，U详情展示已完结及该结果。以上全程只有一张T，不生成新的用户工单，也不套用旧工单的接取经手统计。

## 9. 状态与异常反馈汇总

| 场景 | 页面行为 | 恢复方式 |
| --- | --- | --- |
| 列表／类型加载中 | 展示加载，避免旧条件数据冒充新结果 | 最新请求完成后展示 |
| 无历史／无筛选结果 | 对应空态，不提示系统异常 | 切换状态或进入提交 |
| 无有效模板 | 不出现可提交的伪模板 | 返回首页、稍后重试 |
| 模板配置不合法 | 保留配置，指出字段／选项错误 | 修正后保存 |
| 必填未填、文本超长 | 字段旁提示，阻止提交 | 修改对应字段 |
| 文件不支持／超限 | 不接受文件，说明限制 | 重新选择 |
| 上传失败／播放失败 | 区分上传与查看失败，不误显示成功或未填写 | 重试／移除后重新上传；查看失败重试 |
| 默认处理人不可用 | 不创建未指派工单，保留当前表单会话内容 | 提示稍后重试或联系现有客服 |
| 提交结果未知 | 不诱导创建另一张，核实同次操作结果 | 查询确认或安全重试同次提交 |
| 移交／完结并发冲突 | 不覆盖先成功结果，说明信息已变化 | 刷新后按新权限和状态操作 |
| 无权限／身份失效 | 停止读取和提交，不展示越权缓存 | 恢复原身份或返回可访问页面 |
