## 2. 需求背景与目标

在现有客服能力之外，增加用户主动填写表单申请工单的渠道。后台按业务配置不同工单类型及表单，用户选择类型后填写提交，系统自动指派给该模板配置的客服；客服处理或移交后，填写处理结果并完结。

目标是让用户提交结构化反馈并查看历史申请，让客服在现有“工单处理”的同一列表与详情框架内处理客服创建和用户提交的工单，避免切换两个处理入口。“工单类型”就是“表单模板”；“来源”是创建渠道，两者分别记录。

## 3. 使用用户与权限

| 端口 | 身份 | 已确认的能力 |
| --- | --- | --- |
| H5用户端 | 使用客服页面的用户 | 选择反馈类型、填写表单、提交工单、查看历史申请；展示处理中和已完结两种状态 |
| 管理后台 | 管理员 | 查看全部用户工单、筛选指派给我的工单，可移交、完结全部工单并配置模板 |
| 管理后台 | 客服／模板处理人 | 仅查看和处理当前指派给自己的工单，可移交、填写处理结果并完结；不提供模板配置权限 |
| 其他端 | 无新增身份 | 本次未提出其他端需求 |

上述新增权限口径针对用户提交来源；客服创建工单保留现有权限，合并列表不为其扩大或缩小权限。管理员拥有全部用户工单的查看、移交、完结及模板配置权限；普通客服仅查看和处理当前指派给自己的工单，不因持有详情链接获得其他工单权限。方案建议：组织隔离沿用现有系统，不新增跨组织能力。

## 4. 关联页面与入口

### 4.1 管理后台

保留现有“工单处理”菜单和页面，不再新增独立“用户工单”处理菜单。现有客服创建的工单与H5用户提交的工单放入同一业务列表，共用详情及移交、完结入口；这不约束研发必须采用单一数据库表。

现状依据图1：已有标题／工单号／用户ID搜索、指派给我筛选、状态筛选、查询及“创建工单”；列表已有问题与编号、状态、优先级、当前负责人、下次反馈时间、处理结果和查看详情。

本次增加“来源”列和筛选（全部来源／客服创建／用户提交），保留现有搜索及创建入口。管理员在页面内进入“工单类型配置”，配置H5表单模板；普通客服不显示该入口。现有客服创建表单不强制套用用户模板。

### 4.2 移动端H5

在客服页面“常见问题导航金刚区”下方增加两个卡片：

1. **工单记录**：查看历史申请工单列表，状态为“处理中”“已完结”。
2. **提交工单反馈**：选择后台配置的反馈类型，进入对应表单，填写并提交。

依据图2，卡片放在八个快捷问题图标下方、“常见问题”内容区上方；方案设计为横向两卡。保留原有常见问题内容及底部“人工客服”按钮。

## 5. 需求内容与业务口径

### 5.1 统一工单列表、来源及详情

已确认：

- 管理员可以查看所有用户工单，也可筛选“指派给我的工单”。“我”指当前登录后台账号。
- 工单应关联提交用户、所选模板、用户填写内容、当前处理人、状态及处理结果。
- 后台支持查看用户提交的表单内容，以便处理反馈。

- 来源固定为“客服创建”或“用户提交”，由实际创建渠道记录，不由用户选择，不因移交或完结变化。既有后台创建记录归入客服创建，具体历史识别方式由研发核实。
- 来源与归属、状态及现有关键词条件组合使用；筛选结果必须先满足权限范围。列表统一展示不等于扩大普通客服权限。
- 详情共用基础信息和处理区域，按来源展示现有客服创建内容或用户模板答案；内部备注和操作记录不自动公开到H5。

融合方案：列表保留现有列，新增来源标签；工单类型放在问题标题下方，避免额外扩宽。用户提交工单标题由系统按“模板名称 · 用户标识”生成，不增加用户必填标题，也不截取首个答案。用户工单默认普通优先级，用户不可选择；未设置下次反馈时间显示“—”，不新增提醒规则。分页及查询细节在PRD中说明。

### 5.2 工单移交与完结

已确认：

以下移交与完结规则针对用户提交来源；客服创建来源沿用既有规则。

- 支持将工单移交给其他客服。
- 完结工单复用现有弹窗：处理结果选择“已解决／未解决／转需求”，内部处理结论、处理依据／验证记录、面向用户的结果说明均必填。内部两项仅后台可见，面向用户的结果说明在H5展示；不再简化为单一结果输入框。
- 用户提交后直接进入“处理中”，无需客服接取。移交后仍为“处理中”，接收客服无需接取。
- 管理员可移交、完结全部用户工单；普通客服仅可移交、完结当前指派给自己的工单。
- 完结时填写的处理结果说明在H5工单详情中展示给提交用户。
- H5对用户展示“处理中”和“已完结”两种状态。

用户提交来源的状态流转：提交成功 → 处理中；移交成功 → 处理中（更新处理人）；填写必填处理结果并完结成功 → 已完结。用户提交的工单在后台与H5均无待接取步骤。

客服创建来源沿用既有状态和接取规则。统一后台列表可包含待接取、处理中、已完结；待接取不用于用户提交工单。截图仅显示已完结记录，不能据此推定完整旧流程；现有接取行为以研发核实的既有系统为准，不在本需求中改造。用户结果必填及公开规则不强制套用于现有客服工单。

方案建议：移交成功后更新当前处理人，“指派给我”根据当前归属变化；保留提交、移交、完结的操作记录。完结成功后后台与H5显示已完结；禁止对已完结工单继续移交或重复完结。处理结果说明必填，并向提交用户展示。

### 5.3 工单类型与默认处理人

已确认：

- 后台支持创建工单类型，即配置表单模板。
- 每个模板配置一个处理人，用于按类型自动指派。
- 用户提交某模板对应的工单后，直接指派给该模板配置的客服，不要求用户选择客服。

方案建议：模板名称用于H5“反馈类型”选择；模板需具备有效处理人和可填写的表单配置，才可供用户提交。若处理人不可用，应明确提示并保留用户已填写内容，不显示虚假的提交成功。

模板编辑／停用、处理人离职或停用时的承接策略尚未提出。建议后续设计采用：模板变更仅作用于后续新提交，已提交工单保留提交时的表单与已填写内容，不自动改派存量工单。该建议须随需求审阅确认。

### 5.4 模板字段

| 输入类型 | 已确认能力 |
| --- | --- |
| 文本 | 用户填写基础文本内容 |
| 单选项 | 模板配置选项，用户选择一个 |
| 多选项 | 模板配置选项，用户选择多个 |
| 图片 | 用户上传图片 |
| 视频 | 用户上传视频 |
| 长文本 | 用户填写多行、较长内容 |

- 上述六种输入均支持配置是否必填。
- 单选、多选需要配置选项内容；字段需有可供用户理解的名称。
- 用户选择反馈类型后，按对应模板展示字段、选项及必填标记。
- 必填校验未通过时不能提交，并应指出具体字段。

方案建议：允许配置多个字段并按模板中的顺序展示。文本长度、选项数量、媒体格式／大小／数量限制在PRD阶段提出具体方案，不在需求单中虚构已确认数值。必填媒体需上传成功才算填写完成；上传失败支持重新上传，不应提交缺失附件的工单。

### 5.5 H5提交与历史记录

已确认的提交路径：进入“提交工单反馈” → 选择反馈类型 → 进入模板表单 → 填写并提交 → 生成用户工单并自动指派。

已确认的查询路径：进入“工单记录” → 查看历史申请列表 → 区分处理中与已完结。

方案建议：提交成功后显示工单编号及查看记录入口，记录可进入详情查看已提交内容、状态；已完结工单详情向提交用户展示处理结果说明。提交中防止重复点击，失败保留输入并允许重试；未产生工单时不能展示成功。没有可用模板或没有历史记录时，显示对应空状态。

已确认：H5沿用现有客服用户身份，仅展示“来源为用户提交且提交人为当前用户”的记录及详情；客服在后台为该用户创建的工单不自动进入H5记录。仅工单关联用户相同不足以获得H5访问权限。不新增独立账号体系，内部备注及流转信息不向用户开放。

## 6. 用户使用路径

### 路径一：配置模板

管理员进入“工单处理 → 工单类型配置” → 创建工单类型 → 设置模板名称、表单字段、单／多选项及必填规则 → 配置一个处理人 → 保存有效模板，供H5选择。

### 路径二：用户申请

用户进入H5客服页面 → 在常见问题金刚区下方点击“提交工单反馈” → 选择反馈类型 → 填写对应表单并上传所需附件 → 校验通过并提交 → 系统创建工单并指派给模板处理人，直接进入处理中 → 用户可进入工单记录。

### 路径三：客服处理及移交

后台进入统一“工单处理” → 按需筛选来源为用户提交 → 查看“指派给我的工单” → 打开目标工单并查看用户提交内容 → 自行处理或移交给其他客服 → 当前归属更新，状态仍为处理中，接收人无需接取。普通客服只能操作当前指派给自己的工单，管理员可操作全部工单。

### 路径四：完结与回查

有权限的处理人员打开工单 → 填写必填的处理结果说明并完结 → 工单变为已完结 → 提交用户从“工单记录”查看最新状态，并在详情查看处理结果说明。

### 路径五：管理员查看

管理员进入“工单处理” → 查看两类来源的全部可访问工单 → 按需切换到指派给我的工单 → 查看工单详情；可对全部用户工单执行移交和完结。

## 7. 不允许出现的情况

- 模板与用户选中的反馈类型不一致，或单选、多选选项与模板不一致。
- 未满足必填规则仍提交成功，或媒体上传失败却显示附件已成功提交。
- 自动指派到与提交时模板配置不符的客服，且无明确的移交记录或已确认规则。
- 移交成功后“指派给我”仍按旧归属显示，或操作失败却显示归属已经改变。
- 未填写处理结果说明仍允许完结，或完结失败却显示已完结。
- 完结后H5状态与后台不一致，或提交用户无法在详情查看处理结果说明。
- 普通客服查看或处理非当前指派给自己的工单，或用户查看他人的工单。
- 用户提交工单在提交或移交后进入待接取，要求客服接取后才能处理。
- 新增第二个独立用户工单处理入口，或来源筛选绕过归属权限。
- 将客服创建的内部工单、备注或结果自动公开到H5。
- 将用户提交的无需接取规则强制覆盖客服创建工单的既有流程。
- 未经确认直接将旧需求FR-wenkf-001的接取流程、统计口径或权限套用于本需求。
- 将方案建议或待确认内容标记为用户已经确认。

权限底线：不得通过详情链接绕过已确认的客服归属权限或用户本人限制。方案建议：组织边界沿用现有系统，不新增跨组织数据访问。

## 9. 确认结论与后续细化

2026-11-20补充确认：

- 提交和移交后直接进入／保持处理中，无需接取。
- 管理员可查看全部、移交、完结并配置模板；普通客服仅查看和处理当前指派给自己的工单。
- H5沿用现有用户身份，每位用户仅查看本人提交的工单。
- 完结时处理结果说明必填，并在H5工单详情向提交用户展示。

新增截图确认（2026-11-20）：详情沿用右侧抽屉及处理时间线；客服创建来源截图状态名为“待接收”。完结沿用用户提供的现有弹窗，保留处理结果三选项及三个必填说明区域，区分内部记录与面向用户的结果。

本次融合修订：不新增独立处理菜单；通过来源统一列表和详情，保留客服创建流程，用户提交仍无需接取；H5不展示客服后台创建的内部工单。

本轮关键业务问题已确认，无剩余关键业务待定项。现有详情、客服工单权限与接取操作需在研发评审中核实现状，保持既有规则；截图不视为完整交互说明。模板变更保留历史、不可用处理人处理策略、操作记录、组织隔离和媒体限制仍为方案建议／后续细化项，尚不代表用户逐项确认。
