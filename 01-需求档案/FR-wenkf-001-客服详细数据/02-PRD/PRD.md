## 2. 背景、目标与范围

### 2.1 背景与目标

现有客服列表提供实时接待状态与今日接待、评价数据，管理员无法查看单客服的历史累计接待、每日服务记录及日期范围汇总，也无法导出这些数据。

本需求帮助有客服列表权限的后台用户完成三项任务：

1. 在列表直接了解客服的历史累计接待量。
2. 查看单客服在指定日期范围内的接待、评价和工单数据，并按日查看记录。
3. 导出与页面查询口径一致的Excel文件，用于留存与后续分析。

### 2.2 范围清单

| 功能编号 | 功能 | 本次要求 |
| --- | --- | --- |
| F01 | 客服列表改造 | 新增累计接待列，将容量配置表头改为操作，新增详细数据入口 |
| F02 | 单客服数据详情 | 独立页面展示身份、累计接待、日期汇总与每日记录 |
| F03 | 日期查询 | 全部、今日、昨日、近7天、自定义；默认全部 |
| F04 | 统计规则 | 接待、评价及创建／处理中／已完结工单3项指标 |
| F05 | 数据刷新 | 手动刷新，显示统一统计截至时间 |
| F06 | 数据导出 | 单客服Excel，含汇总信息和全部所选日期每日记录 |
| F07 | 权限与异常 | 沿用现有权限，隔离当前组织，处理查询与导出异常 |

### 2.3 不在本次范围内

- 统一「管理与运营 → 数据统计」页面、列表全局日期筛选、可交互的数据排序。
- 跨组织查询或导出、新增角色及权限项。
- 会话、评价或工单逐条明细下钻。
- 列表批量导出、多客服合并导出。
- 工单历史日末快照或按接取、流转、完结动作日期统计。
- 其他工单指标、响应／处理时长、在线／离开时长。
- 客服容量规则、工单处理流程及用户端改造。

## 3. 用户、权限与组织约束

### 3.1 使用身份

使用者为拥有现有「客服列表」模块权限的后台用户，具体身份由现有角色管理决定。管理员只是其中一种身份，不增加管理员专属限制，也不新增客服本人或主管专属规则。

### 3.2 权限矩阵

| 能力 | 权限要求 | 范围 |
| --- | --- | --- |
| 查看新增累计接待列 | 现有客服列表模块权限 | 当前组织的列表内客服 |
| 进入详细数据及查询 | 现有客服列表模块权限 | 当前组织内目标客服 |
| 导出及获取导出文件 | 现有客服列表模块权限 | 当前组织内目标客服、当前有效查询结果 |
| 调整容量 | 原有容量调整权限及条件 | 完全沿用现有规则 |

- 页面访问、数据查询、导出发起、任务状态查询和文件下载均须校验权限及组织范围。
- 不得仅通过隐藏按钮控制访问；直接访问详情或文件也要校验。
- 权限撤销、切换组织或目标不在当前组织可访问范围时，不得继续显示或下载原组织数据。
- 当前列表中停用、离开或容量操作为只读的客服，仍可由有模块权限者查看历史数据；不因服务状态将历史数据置0。

## 4. 页面结构与主流程

### 4.1 页面关系

「管理与运营 → 客服列表」→ 对应行「详细数据」→「客服详细数据」独立页面。

不新增左侧菜单。详情通过返回按钮或面包屑返回客服列表；同一组织内返回时恢复列表原搜索、状态筛选、分页及滚动位置。

### 4.2 主流程

1. 用户进入当前组织客服列表，查看累计接待。
2. 点击目标客服「详细数据」，校验权限及目标归属。
3. 默认按「全部」查询，展示历史累计、范围汇总及每日记录。
4. 用户切换日期，结果刷新且每日记录回到第1页。
5. 用户可手动刷新当前条件，获得新的统计截至时间。
6. 用户导出当前成功查询结果，生成并下载Excel。

## 5. F01：客服列表改造

### 5.1 列调整

保留现有列及功能，在「今日接待人数」前插入「累计接待」；最右侧「容量配置」改名为「操作」。

相关列顺序为：客服 → 当前状态 → 本组织占用／配额 → **累计接待** → 今日接待人数 → 今日评价 → 好评·4—5星 → 中评·3星 → 差评·1—2星 → **操作**。

### 5.2 累计接待

- 展示当前客服在当前组织从2026-10-30起截至列表统计时间的接待会话次数，单位为次，整数展示，可使用千位分隔。
- 表头说明：「自2026-10-30起的累计接待会话次数；转接会话为每位接待过的客服各计1次。」
- 真实无记录显示0，加载中显示占位，失败显示「--」及重试反馈，不以0表示失败。
- 沿用现有列表刷新节奏，不增加独立自动刷新机制。列表与详情比较时须以相同统计时间为前提。
- 现有「今日接待人数」名称本次保留，其实际口径已确认与会话次数一致。

### 5.3 操作列

- 保留「调整容量」及现有只读、可用或不可用表现。
- 对具有模块权限的可访问客服行新增「详细数据」，与容量调整权限独立。
- 「详细数据」为页面导航，不以客服姓名作为本次新增入口。
- 不新增累计接待或评价数的点击下钻。

## 6. F02：客服详细数据

### 6.1 页面模块

| 模块 | 内容与要求 |
| --- | --- |
| 页头与导航 | 标题「客服详细数据」、返回客服列表入口、现有后台导航 |
| 身份信息 | 客服姓名、客服编号、当前组织名称 |
| 历史累计 | 「累计接待」及次数，说明起点为2026-10-30，不受日期筛选影响 |
| 日期与操作区 | 全部／今日／昨日／近7天／自定义、实际起止日期、刷新数据、导出数据 |
| 所选日期汇总 | 接待会话数、评价数、好评数、中评数、差评数、创建工单数、处理中工单数、已完结工单数 |
| 每日记录 | 按天一行，含日期及上述8项范围指标，默认日期倒序，每页20条 |
| 统计说明 | 统计截至时间、工单日期及当前状态口径、评价提交日期口径等必要提示 |

### 6.2 汇总与每日记录关系

- 汇总覆盖完整所选范围；分页仅改变每日记录的可见行。
- 每日记录包含范围内每个自然日；无记录的日期各指标显示0。
- 同一次统计结果下，每项范围汇总等于所有日期行对应指标之和。
- 历史累计接待独立于日期范围；选择「全部」时与范围接待会话数相等。
- 评价数等于好评数＋中评数＋差评数，不新增评价率、完结率等派生指标。
- 创建工单数、处理中工单数、已完结工单数的对象集合不同，不能相互加减推导，不展示三者合计。
- 每日记录是日期聚合数据，行和数字不跳转至逐条业务明细。

### 6.3 常驻口径提示

在日期汇总及每日记录附近提供简洁说明，可展开完整规则：

> 接待按开始接待日期统计，评价按提交日期统计，工单按创建日期统计。工单状态为统计截至时间的当前状态，不代表历史当日状态。

已完结工单指标补充提示：曾接取经手的工单完结后均计入；不同客服的已完结数不能直接相加作为组织去重总量。

## 7. F03：日期规则

### 7.1 时间基础

- 统一采用北京时间Asia/Shanghai，日期为自然日。
- 所选起始日包含00:00，结束日包含整日；涉及今日的数据截止于本次统计截至时间。
- 展示日期格式为YYYY-MM-DD，统计截至时间精确到秒并标注北京时间。
- 历史起点固定为2026-10-30，日期不早于该日、不晚于今日。

### 7.2 选项定义

| 选项 | 范围 |
| --- | --- |
| 全部（默认） | 2026-10-30至今日，不受自定义1年跨度限制 |
| 今日 | 今日00:00至统计截至时间 |
| 昨日 | 昨日完整自然日 |
| 近7天 | 今日及此前6个自然日；如早于历史起点，截取到历史起点 |
| 自定义 | 用户指定起止日期，包含首尾日，跨度最多1年 |

自定义1年按连续12个日历月计算，不固定为365天：以起始日加1个日历年为不包含的右边界，结束日必须早于该边界；起始日为2月29日时，右边界按次年3月1日计算。例如2026-10-30至2027-10-29合法，至2027-10-30超限；同时仍须满足不晚于今日。

### 7.3 操作与校验

- 快捷选项点击即查询；自定义选择起止日期后点击「查询」生效。
- 自定义编辑期间保留上次成功结果及其实际日期标签，但暂禁导出，避免将草稿条件误认为结果条件；取消编辑恢复已生效条件。
- 必填任一日期缺失时提示「请选择完整日期范围」；开始晚于结束提示「开始日期不能晚于结束日期」。
- 超出历史起点、未来日期或1年限制时阻止查询并在日期区说明原因；合法快捷范围为空时禁用该选项并说明。
- 切换范围或刷新后每日记录回到第1页；跨午夜手动刷新时，快捷范围按当时日期重新计算，自定义保持原日期。
- 查询并发时仅展示最后一次有效条件的结果，过期请求不得覆盖新条件数据。

## 8. F04：统计口径

### 8.1 通用原则

- 所有指标同时限定当前组织和目标客服，组织数据隔离不能由前端参数决定。
- 统计去重依赖会话、评价、工单的业务标识，不因分页、重试或数据关联产生重复。
- 历史累计仅统计历史起点以来的数据，页面使用「自2026-10-30起」避免理解为产品上线前的全部历史。
- 每次查询以统一时间T形成统计结果；分页、汇总与导出均使用该结果，不在翻页或导出时重新计算状态。

### 8.2 接待会话数

| 要素 | 规则 |
| --- | --- |
| 统计对象 | 目标客服在当前组织实际接待过的会话 |
| 去重单位 | 同一组织、同一客服、同一会话计1次 |
| 日期归属 | 开始接待时间；在客服维度采用该客服对该会话首次开始接待的时间归日，跨天持续接待不重复计数 |
| 转接 | 每位实际接待过的客服各计1次；仅分配但未接待不计；转回同一客服不再增加 |
| 用户复访 | 同一用户发起不同会话分别计算 |

跨日转接示例：会话S由A在11-01 23:50开始接待，B在11-02 00:10接手，则A计入11-01、B计入11-02，各1次；后续再次转回A不新增次数或改变A归属日期。此为“每个客服按开始接待时间归日”的执行说明。

### 8.3 评价指标

| 指标 | 规则 |
| --- | --- |
| 评价数 | 归属目标客服、在所选日期提交的有效1—5星评价记录数 |
| 好评数 | 上述评价中4—5星数量 |
| 中评数 | 上述评价中3星数量 |
| 差评数 | 上述评价中1—2星数量 |

- 按评价提交日期归日，不能按会话开始日期归日。
- 转接会话评价归属最后接待客服，前序接待客服不分摊该评价。
- 未评价会话不计入评价数；不改造现有评价提交、有效性或修改规则，不虚构评价记录。

### 8.4 工单指标

先按当前组织和工单创建日期筛选工单集合，再判断与客服的关系及统计时间T的状态。

| 指标 | 客服关系 | 状态条件 | 去重 |
| --- | --- | --- | --- |
| 创建工单数 | 创建人为目标客服 | 任意现有状态 | 每个工单1次 |
| 处理中工单数 | 目标客服已实际接取，且当前由其处理 | 当前状态为处理中 | 每个工单1次 |
| 已完结工单数 | 目标客服曾实际接取经手 | 当前状态为已完结 | 每个工单1次 |

- 仅创建不代表经手；分配、流转给某客服但未接取也不代表经手。
- 「待接取」不计任何客服的处理中数，历史经手关系仍保留。
- 工单流转后，从原处理客服处理中数移除；新处理客服实际接取后计入其处理中数。
- 完结后，所有曾实际接取经手的客服均增加该工单的已完结数，创建人若未接取不计已完结。
- 多次接取同一工单不重复计算；转交不删除已有经手关系。
- 日记录按工单创建日期放入对应行，不放入接取日、转交日或完结日。
- 即使工单在所选日期外接取或完结，只要创建日期在范围内，仍按T时的关系和状态计算；创建日期不在范围内则不计入。
- 用户确认接待与经手记录齐全；上线前需校验2026-10-30起数据可用，缺失时须修复，不用0伪装无业务。

### 8.5 工单现有流程对照

| 动作 | 结果状态 | 对统计的影响 |
| --- | --- | --- |
| A创建、等待B接取 | 待接取 | A创建数+1，B未接取不增加经手指标 |
| B接取 | 处理中 | B处理中数+1，保留B经手关系 |
| B流转给C、等待接取 | 待接取 | B处理中数-1，C不增加，保留B经手关系 |
| C接取 | 处理中 | C处理中数+1，保留C经手关系 |
| C执行完结 | 已完结 | C处理中数-1，B与C各计1个已完结；A若未接取不计 |

以上增减均指工单创建日期被查询范围包含、且前后分别刷新后观察到的变化，不要求页面自动实时推送。

## 9. F05：查询、刷新与统计一致性

### 9.1 查询触发

进入详情、切换快捷范围、提交自定义日期、点击「刷新数据」触发完整查询，不自动轮询。分页只读取当前统计结果对应的日期行，不重算数据。

### 9.2 统一结果

- 一次成功查询确定目标组织、客服、实际日期范围、统计截至时间T、历史累计、8项范围汇总及完整每日结果。
- 页面显示「统计截至：YYYY-MM-DD HH:mm:ss（北京时间）」。
- 工单当前状态明确为T时状态；查询成功后发生的状态变化在下一次刷新体现。
- 结果有效期内，后台变化不影响当前分页或导出。结果过期／失效时提示「当前统计结果已失效，请刷新数据」，禁止混用新旧数据。
- 切换客服或组织时清除前一目标结果，防止迟到响应串入。

### 9.3 控件状态

| 状态 | 页面 | 导出 |
| --- | --- | --- |
| 首次加载 | 指标及表格占位，身份信息与查询范围清晰可见 | 禁用 |
| 查询／刷新中 | 显示加载状态，不将旧值显示为新范围结果 | 禁用 |
| 成功且有数据 | 正常展示 | 可用 |
| 成功但全为0 | 指标为0，保留日期行，提示该范围暂无服务数据 | 可用，可导出全0结果 |
| 查询失败 | 明确失败、保留条件并提供重试，不展示伪造0 | 禁用，成功重试后恢复 |
| 无权限／不可访问 | 显示对应反馈，清除敏感数据 | 禁用 |

## 10. F06：Excel导出

### 10.1 导出范围

- 按当前成功查询的组织、客服、实际日期范围及统计截至时间导出一个`.xlsx`文件。
- 无论当前表格处于哪一页，都导出该范围的所有日期行，包括全0日期。
- 「全部」可导出超过1年的完整历史，不套用自定义跨度限制。
- 不导出逐条会话、评价、工单记录或其他客服数据。

### 10.2 文件结构

| 工作表 | 必须包含的内容 |
| --- | --- |
| 汇总信息 | 需求对应数据标题、组织名称、客服姓名／编号、日期选项与实际起止日期、统计截至时间、导出生成时间、历史起点、历史累计接待、8项范围汇总、关键统计口径说明 |
| 每日数据 | 日期、接待会话数、评价数、好评数（4—5星）、中评数（3星）、差评数（1—2星）、创建工单数、处理中工单数、已完结工单数 |

- 每日数据顺序与页面一致，为日期倒序；不增加汇总行冒充日期记录。
- 客服编号按文本保留前导0，计数为非负整数，日期为可识别日期，便于后续分析。
- 统计截至时间与导出生成时间分别展示，二者不混用。
- 口径说明至少包括历史起点、转接计数、评价日期与归属、工单按创建日期及当前状态统计、已完结数据跨客服不可直接相加。
- 文件名：「客服详细数据_组织名_客服编号_起始日期_结束日期_YYYYMMDDHHmmss.xlsx」。末段为导出生成时间，不合法文件名字符替换为下划线。

### 10.3 导出流程与状态

1. 点击「导出数据」，再次校验权限及当前统计结果有效性，绑定该结果生成后台任务。
2. 按钮显示「导出中」，禁止同一页面重复提交；提供「文件生成中，请稍候」反馈。
3. 大范围同样生成单文件，后台任务展示生成状态，不阻塞用户查看现有结果，不截断历史日期。
4. 任务成功后尝试下载；同时提供「下载文件」入口，便于浏览器未触发下载时重试。
5. 失败显示「导出失败，请重试」，保留查询条件和结果，恢复导出按钮；结果已失效则先要求刷新。

导出任务生成中暂禁切换日期和刷新，避免将任务与另一查询结果混淆；查看分页不影响任务。离开页面或切换组织无需强制等待，返回后可重新查询导出，本次不新增全局导出任务中心。离开后旧任务不得向其他客服或组织页面触发下载。任务成功或失败后解除控件限制。

## 11. F07：边界与异常处理

| 场景 | 要求 |
| --- | --- |
| 用户无模块权限或权限被撤销 | 拒绝查询与下载，提示无访问权限，提供返回可访问页面入口 |
| 目标客服不存在／不属于当前组织可访问范围 | 提示「该客服不存在或当前不可访问」，不展示其他组织信息 |
| 客服停用或离开 | 历史数据仍可查，维持权限限制，不因服务状态清空数据 |
| 切换组织 | 清空原组织详情与任务展示，返回新组织客服列表，由用户重新选择客服 |
| 日期输入不合法 | 阻止查询，明确字段错误，不静默纠正为其他范围 |
| 网络超时／统计失败 | 显示失败及重试，不以0替代；重试沿用条件 |
| 每日记录翻页失败 | 保留已成功汇总及其截至时间，仅表格显示失败并重试，禁止混入其他统计结果 |
| 统计结果过期 | 要求完整刷新后继续翻页或导出，不重新计算部分指标冒充原结果 |
| 查询期间重复操作 | 只接受最后有效查询结果；导出不可用 |
| 导出失败或下载被浏览器阻止 | 分别提供重新导出或下载文件入口，不重复生成未明确失败的任务 |
| 历史数据异常缺失 | 作为数据异常处理，不显示为真实无业务的0 |

所有提示须保持后台现有风格，不泄露其他组织客服或导出文件内容。

## 12. 数据质量与实现约束

- 统计需要可识别的组织、客服、会话、评价、工单标识，接待开始时间、评价提交时间、工单创建时间、创建人、接取经手关系、当前处理人及状态。
- 存量工单状态仍为待接取／处理中／已完结，不为统计新增业务状态。
- 多次接取与转接必须正确去重；组织内多人经手数据不得用单一当前处理人替代全部经手关系。
- 查询汇总、每日记录、历史累计及导出应可在同一截至时间保持一致；实现方式由研发确定，但不可在导出时改取最新数据。
- 权限变化以当前有效权限为准，即使存在已生成文件也不能绕过校验。
- 客服列表新增数据不得影响原有接待分配、状态切换、容量调整和角色管理。
- 本文不承诺未经评估的接口响应秒数；评审时由研发依据实际数据量验证查询、翻页及全部历史导出可用性，不能通过静默缩小范围满足性能要求。

## 13. 验收标准

| 编号 | 场景／操作 | 预期结果 |
| --- | --- | --- |
| AC01 | 进入客服列表 | 今日接待人数前出现累计接待；容量配置改为操作；调整容量按原规则，详细数据可进入对应客服 |
| AC02 | 有查看权限但无容量调整权限 | 可查及导出数据，不能因此获得容量调整能力 |

| AC17 | 成功查询后工单状态改变，再翻页及导出 | 仍与原统计截至时间一致；刷新后才展示变化 |
| AC18 | 点击导出并等待生成 | 同一Excel含2个工作表，含身份／组织／日期／截至时间／累计／汇总／全量日记录；无逐条业务明细 |
| AC19 | 查询或刷新中、失败、条件处于未提交编辑状态 | 不允许导出错误或旧条件数据；加载失败不显示为0 |
| AC20 | 直接访问无权限详情、替换其他组织客服或下载文件 | 被拒绝，不返回跨组织数据 |
| AC21 | 快速切换日期或切换组织时旧请求返回 | 旧结果不能覆盖最新范围或新组织页面 |
| AC22 | 导出失败、文件下载受阻 | 前者可重试且不丢条件；后者可重新下载已生成文件 |
| AC23 | 停用客服仍在当前组织列表 | 有权限者可正常查看其历史累计及详情，数据不因停用归0 |
| AC24 | 查看或导出已完结工单 | 有明确经手口径说明，不把多客服相加解释为组织去重总量 |
