## 2. 需求背景

当前后台「管理与运营 → 客服列表」展示客服当前状态、接待占用与配额、今日接待人数、今日评价及好评／中评／差评数量等信息，支持调整接待容量。

管理员目前只能查看今日服务数据，无法在单个客服维度查看历史累计接待情况、每天的接待及工单数据，也无法按日期范围查看汇总。需要在现有客服列表提供累计接待数据和单个客服详细数据入口，支持日期查询和Excel导出，以便了解客服历史工作情况并留存统计结果。

| 端口 | 用户身份类型 | 本次使用方式 |
| --- | --- | --- |
| 前端／用户端 | 咨询用户 | 本次无新增页面、入口或操作 |
| 管理端 | 具有「客服列表」模块权限的后台用户，包括拥有该权限的管理员等现有角色 | 查看当前组织的客服列表、累计接待、单客服详细数据，并导出该客服数据 |

- 「调整容量」保留原有权限与行为；有查看权限不代表获得调整容量权限。
- 详细数据及其导出不得绕过现有权限与组织范围限制。

### 4.2 客服数据详情

页面归属：当前组织下的单个客服。入口为客服列表对应行的「详细数据」。

包含以下内容：

- 该客服在当前组织内的历史累计接待总数。
- 日期选择：全部、今日、昨日、近7天、自定义日期范围，仅作用于该客服详情；默认展示全部汇总数据。

- 每日接待、评价及工单数据记录。
- 数据导出操作，以及返回客服列表的路径。

## 5. 数据内容及确认口径

### 5.1 接待数据

| 指标 | 含义与范围 |
| --- | --- |
| 累计接待 | 当前客服在当前组织内的历史累计接待会话次数，不随详情日期选择变化 |
| 所选日期接待总数 | 当前客服在所选日期范围内的接待会话次数 |
| 每日接待数 | 按天展示该客服的接待会话次数 |

- 接待量按会话次数统计，不按用户人数去重；同一用户发起不同会话分别计算。
- 会话按开始接待时间归日；转接会话为每位接待过的客服各增加1次，同一客服对同一会话只计1次。现有今日指标与该会话次数口径一致。
- 现有列表字段「今日接待人数」是截图中的现有名称；详情数据及新增累计接待须明确采用会话次数口径，避免将其理解为独立用户数。

### 5.2 评价数据

详情的日期汇总与每日记录覆盖现有列表中的评价指标：评价数、好评数（4—5星）、中评数（3星）、差评数（1—2星）。日期汇总不再局限于今日。

评价按提交日期统计；转接会话的评价归属最后接待的客服。

### 5.3 工单数据

本次最终确认的工单指标仅为以下3项。补充截图中的其他指标不自动纳入本次需求。

| 指标 | 确认口径 |
| --- | --- |
| 创建工单数 | 仅统计当前客服亲自创建的工单 |
| 处理中工单数 | 该客服已接取、且当前仍由该客服正在处理的工单数，实际状态为「处理中」；不包含「待接取」、已转交或已完结的工单 |
| 已完结工单数 | 当前客服曾经手过、且工单当前状态为「已完结」的工单数 |

- 工单按创建日期筛选；每日记录按工单创建日期分组。
- 创建行为本身不计入经手，实际接取才计入经手；创建工单数独立按本人创建统计。
- 状态指标展示所筛选工单的当前状态，不表示历史当日结束时的状态。
- 同一工单在同一客服的同一指标内去重，不因多次经手而重复计数。
- 工单转交后仍保留原客服的经手关系，但不再计入原客服「处理中工单数」；接收方实际接取并正在处理时计入其「处理中工单数」。
- 工单完结后，计入所有曾实际接取经手客服的「已完结工单数」，而非仅计入最终完结人。因此，不同客服的已完结工单数据不可直接相加作为组织唯一已完结工单总量。
- 创建工单数与状态指标的统计集合不同，不要求「处理中 + 已完结 = 创建工单数」。
- 历史日期下的状态统计可能随着工单当前状态或经手关系变化而更新，不能解释为历史快照。

现有工单流程及状态（本需求仅使用该流程统计，不改造流程）：

1. 创建工单：等待对应处理人接取，状态为「待接取」。
2. 处理人接取：状态为「处理中」。
3. 流转给其他客服：等待其他客服接取期间，状态为「待接取」；接取后为「处理中」。
4. 完结工单：当前已接取且正在处理的客服可执行完结，操作后状态为「已完结」。

### 5.4 日期、历史与每日记录

- 可统计历史起点为2026年10月30日；接待与工单经手记录齐全。
- 默认查询全部汇总数据，提供「全部」选项以便切换后恢复。
- 近7天包含今日；自定义日期包含首尾日，单次自定义日期跨度最多1年。「全部」不受该跨度限制，始终覆盖2026年10月30日起的全部可统计历史。
- 查询范围内无业务数据的日期保留每日记录，各指标显示0；加载失败不以0代替。
- 每日记录采用表格，按日期从近到远固定排列，每页20条；分页不改变范围汇总及导出范围。该固定排列不新增用户排序功能。
- 详情采用独立页面，保留返回客服列表入口。

### 5.5 数据刷新与一致性（方案设计）

- 进入详情、确认切换日期时查询数据；提供「刷新数据」操作，不自动轮询。
- 历史累计、范围汇总与每日记录使用同一次统计结果，展示统一的「统计截至时间」。切换分页沿用该结果。
- 处理中及已完结指标的「当前状态」以本次统计截至时间为准。
- 导出沿用当前成功查询的统计结果和截至时间，覆盖所选范围全部每日记录，不仅是当前页。需要最新数据时先刷新再导出。
- 查询或刷新期间禁止导出；查询失败显示失败反馈并允许重试，不将旧结果当作新范围结果。

### 5.6 数据导出

在单个客服「详细数据」页导出一个Excel（`.xlsx`）文件，内容包括：

1. 客服身份信息、当前组织信息、所选日期范围。
2. 历史累计接待总数。
3. 所选日期范围内的接待、评价及3项工单指标汇总。
4. 所选日期范围内的每日数据记录。

导出数据与当前详情查询保持相同客服、组织、日期范围和统计口径；历史累计接待须单独标明其为全历史口径。文件不包含逐条会话或逐条工单明细，不新增客服列表批量导出。

导出交互方案：

- 工作表分为「汇总信息」「每日数据」；汇总信息包含统计截至时间及必要口径说明。
- 文件名采用「客服详细数据_组织名_客服编号_起始日期_结束日期_导出时间.xlsx」；全部范围使用实际历史起点与统计结束日期，文件名不合法字符替换为下划线。
- 文件生成期间显示「导出中」并防止重复提交；完成后下载，失败时显示失败提示并允许重试，保留当前查询条件。
- 大范围数据通过后台生成同一个Excel文件，展示生成状态；导出仍须使用本次查询统计结果。具体处理方式在PRD阶段展开。

## 6. 用户使用路径流程

### 路径一：查看累计接待

具有客服列表权限的后台用户进入当前组织 → 打开「管理与运营 → 客服列表」→ 查看各客服「累计接待」数据。

### 路径二：查看单个客服详细数据

进入客服列表 → 定位目标客服 → 点击该行「详细数据」→ 确认客服与组织 → 查看历史累计接待、日期汇总及每日记录。

### 路径三：按日期查询

进入客服详情（默认全部汇总）→ 选择全部／今日／昨日／近7天／自定义日期范围 → 查看对应日期范围汇总与每日记录 → 按需切换日期。

日期切换仅改变日期汇总和每日记录，历史累计接待仍展示全历史累计值。

### 路径四：导出单个客服数据

进入客服详情 → 选择日期范围 → 查看该范围数据 → 发起导出 → 获取包含身份、组织、日期、历史累计、范围汇总及每日记录的Excel文件。

### 路径五：调整容量

进入客服列表 → 在「操作」列点击原有「调整容量」→ 按原有权限与流程操作。

## 7. 不允许出现的情况

- 无客服列表权限的用户通过详情链接或导出访问数据。
- 查询、页面展示或导出混入其他组织的数据，或混入其他客服的数据。
- 将接待会话次数误算成独立用户数，或将所选日期接待总数标为历史累计接待。
- 日期变化后，汇总、每日记录、导出仍使用旧日期或出现范围不一致。
- 同一客服对同一工单多次经手导致同一指标重复计数。
- 工单转交后丢失原客服已确认应保留的经手统计。
- 把当前工单状态解释为历史当日状态，或把创建数与状态数强行做加总校验。
- 将不同客服的经手工单数直接相加并标为组织去重工单总量。
- 数据加载失败或历史数据缺失时，以虚构数值或未经确认的0值表示真实结果。
- 将原有「调整容量」操作取消，或因新增数据查看能力扩大容量调整权限。
