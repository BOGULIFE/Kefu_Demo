# 右豹在线客服 · 需求交付门户

## 打开方式

在项目根目录或本目录打开 `index.html`，无需安装依赖。保留「00-交付门户」与「01-需求档案」的相对位置。通过本地HTTP服务打开同样可用。

## 页面组织

- 左侧「概览」展示全部已接入需求，支持按名称／编号搜索和状态过滤。
- 左侧Demo导航按待评审、待开始、开发中、已上线、已废弃分别分组，组可折叠。
- 当前接入FR-wenkf-001「客服累计接待与详细数据」。初始状态按交付阶段设为「待评审」，不表示实际研发进度；可在概览或详情修改，状态只保存在当前浏览器。
- 进入需求后，顶部只渲染其配置中涉及的客户端，并固定保留「业务流程」。FR-wenkf-001仅涉及管理后台，因此不展示移动端H5标签。
- 选择客户端，下方左侧列出主要场景和状态异常，右侧直接展示该场景的可交互Demo。
- 业务流程为可缩放、滚动的SVG流程图，包含权限校验、日期查询、失败重试、数据查看和导出分支；业务节点可跳转对应场景。
- 支持放大演示、独立打开Demo、重置当前场景、下载已有需求单／PRD／UX需求表。

## 后续接入

需求目录配置位于 `requirements.js`。新增需求时由需求方提供编号，不自动编定。

1. 在配置数组增加需求编号、名称、描述、状态、更新时间和文档路径。
2. 在clients中配置实际涉及端口。管理后台使用`id: 'admin', viewport: 'desktop'`；移动端H5可使用`id: 'h5', name: '移动端H5', viewport: 'mobile'`，以手机画框展示。
3. 每个客户端的scenes配置场景编号、名称、描述、分类和可直接打开的Demo URL。URL应选择对应初始场景，不仅是普通首页。
4. 补充该需求自身业务流程与说明。当前SVG流程对应FR-wenkf-001，新增不同业务需求时需扩展流程渲染，不能直接复用旧业务流程冒充。
5. 仅配置真实需求；当前未把参考图片中的其他需求作为本项目需求录入。

## 交付文件

| 文件 | 用途 |
| --- | --- |
| index.html | 交付门户入口 |
| delivery.css | 交付门户视觉与布局 |
| delivery.js | 概览、导航、场景、状态和业务流程交互 |
| requirements.js | 需求目录、客户端与场景配置 |
| ../01-需求档案/FR-wenkf-001-客服详细数据/04-静态Demo/ | 客服数据Demo，支持场景深链接及内容嵌入模式 |

嵌入模式只隐藏原Demo的外围导航，不改变其业务演示规则；独立打开仍可看到完整后台。所有演示数据及导出文件均为模拟内容。门户状态不与真实项目管理系统同步，不提供多用户协作和云端发布。
